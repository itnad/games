# 2026-11-12 터치 목표 표시와 건설 접근성 보완

사용자 보고: 유닛 선택 후 위치를 터치해도 목표 표시가 없고 생산한 일꾼의 건설을 진행하기 어렵다.

## 원인과 수정

- 메인 사이트의 모바일 `footer { align-items:flex-start }`가 전장 하단 grid에도 적용됐다. 명령 패널이 배정된 행에 맞춰 늘어나지 않고 내용 높이로 화면 밖에 넘쳤다. 배포본 360×640에서 패널 하단은 905px, 서플라이 디포 버튼은 694~766px에 놓였다. 게임 푸터는 명시적으로 stretch하고 패널의 최소 높이를 0으로 제한해 자체 스크롤을 사용한다.
- 일꾼 헤더에 항상 보이는 `건설` 진입 버튼을 두고, 건물 목록은 별도의 스크롤 메뉴에서 표시한다. 본부·병력·선택 없음에는 `일꾼 선택` 바로가기를 제공한다. 선택이 바뀌거나 건설 모드에 진입하면 패널을 처음으로 되돌린다.
- 건물 목록을 비용 부족만으로 비활성화하지 않는다. 부족한 미네랄/가스와 선행 건물을 표시하고 배치 미리보기를 볼 수 있다. 실제 비용·선행 조건 검사는 유지하며 조건 미충족 시 `건설 확정`은 비활성화한다. 확정/취소는 명령 패널 첫 줄에 둔다.
- 일꾼 몸체를 직접 누르면 자원 채취 터치 범위와 겹쳐도 일꾼을 선택한다. 실제 자원 중심(완성된 가스 건물 포함)을 누르는 채취 조작은 유지한다.
- 이동·공격 이동·순찰·집결지·채취·건설 명령 입력 위치에 900ms 동안 원형 조준 표시를 보여 준다. 카메라 이동/확대에도 같은 월드 위치를 유지하고 크기는 화면 픽셀 기준으로 일정하게 표시한다. 이는 입력 피드백이며 엔진 도착/경로 승인 상태를 뜻하지 않는다. 시뮬레이션·저장 형식은 바꾸지 않는다. 카메라 드래그·핀치·일시정지 중 입력은 새 표시를 만들지 않는다.

## 검증

`npm test`로 기존 게임/한국어 조사 감사, 타입과 결정적 엔진 회귀를 확인한다. `touch-feedback.test.ts`는 위치/명령별 표시와 스냅샷 불변성, 자원 근처의 일꾼 선택, 가스 건물 채취를 검증한다.

`python tools/stark-rift-lab/touch-build-smoke.py --url <origin>`은 360×640·390×844에서 화면 밖 자동 스크롤이나 DOM 클릭 우회 없이 실제 터치로 일꾼 선택 → 건설 메뉴 → 부족 비용 안내/취소 → 이동 위치 표시/소멸 → 배치/확정 → 실제 서플라이 디포 완성을 확인한다. 테스트용 자원 주입이나 시간 가속은 사용하지 않는다. 원본 배포본 측정과 최종 로컬/배포본 결과는 검증 영수증과 함께 보관한다. 실제 기기/GPU 검증과 최종 아트는 별도 항목이다.
