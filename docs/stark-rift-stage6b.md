# 단계 6B — 영구 은폐·탐지·수송

2026-11-12. 엔진 `0.12.0-stage6b`, 저장·스키마 11, 통신 12. 단계 6A 버로우에 이어 다크 템플러·옵저버와 세 종족 수송을 연결한다. 능동 클로킹과 모든 종족 기술을 완료했다는 의미는 아니다.

## 바로 확인

`/stark-rift-dev` → **특수 연습** → 종족 → 새 테스트 시작. 준비된 수송선에서 **탑승 → 1번/2번 부대 슬롯 → 지시 취소**로 병력을 태운다. **전체 하차 → 전장 또는 미니맵 지점**으로 이동 후 하차한다. 탑승 유닛 초상화를 짧게 터치하면 개별 하차하며 길게 누르면 정보만 표시한다. 프로토스는 **옵저버 선택** 후 전장 위치를 터치해 탐지기를 움직일 수 있다. 특수 연습은 제공 병력·필요한 보급 건물·저그 수송/버로우 연구가 있는 별도 저장 모드다.

기지 운영에서는 선행 건물을 짓고 원작 비용을 내야 한다.

| 종족 | 새 연결 |
| --- | --- |
| 테란 | 팩토리 → 스타포트 → 컨트롤 타워 → 드롭십. 자신의 스타포트에 붙은 타워가 필요하다. |
| 저그 | 스포닝 풀 → 해처리의 레어 변태(150/100, 625틱) → 오버로드 수송 연구(200/200, 1,000틱). 라바 생산은 변태·연구와 병행한다. |
| 프로토스 | 사이버네틱스 코어 → 시타델 → 템플러 아카이브 → 게이트웨이의 다크 템플러. 코어 → 로보틱스에서 셔틀, 옵저버토리 이후 옵저버. |

## 구현 범위

- BWAPI v4.4.0 원작 자료에서 11개 유닛/건물과 Warp Blades, Ventral Sacs, 수송 공간·공중·탐지·영구 은폐 플래그를 추출했다. 기존 30개와 합쳐 41개다. `data/special-original.json`에 출처·SHA256을 보관한다. `python tools/stark-rift-data/extract-special.py <unit.cpp·weapon.cpp·upgrade.cpp 폴더>`로 오프라인 재생성한다. 기존 원작 JSON과 이전 버전 해시는 보존한다.
- 다크 템플러·옵저버의 영구 은폐와 옵저버 탐지 11타일. 현재 시야와 살아 있는 탐지기가 모두 있어야 적 은폐 유닛을 표시·선택·공격한다. 다크 템플러는 원작 40 일반 피해·30프레임 주기·15픽셀 사거리와 지상 무기 업그레이드 +3을 적용한다. 옵저버는 비무장 공중 유닛이다.
- 탐지되지 않은 공격자는 위치 경고만 전달한다. 렌더 패킷에 공격자의 내부 ID·무기 이름·유닛 정체를 전달하지 않는다. 아군 및 탐지된 은폐 유닛은 반투명 실루엣으로 표시한다.
- 드롭십·셔틀·수송 연구 완료 오버로드는 각각 8칸이다. 마린/일꾼/저글링 1칸, 질럿/히드라/다크 템플러 2칸, 벌처/탱크/드라군 4칸 등 실제 원작 공간을 적용한다. 탑승 대기도 공간을 예약해 초과 탑승을 막는다. 선택한 수송선 중 공간이 있고 가까운 수송선에 배정한다. 부대 탑승 지시는 가까운 병력부터 보낸다.
- 병력은 수송선으로 걸어가 탑승한다. 접근할 수 없으면 대기하며 수송선을 지상 가까이 이동하거나 지시를 취소할 수 있다. 병력에 새 명령을 내리면 기존 탑승 예약을 해제한다. 수송선의 정지/수송 지시 취소는 접근 명령을 정리하며 이미 탑승한 병력은 유지한다.
- 탑승 병력은 엔티티·체력·운반 자원·인구·부대·대열·태세를 보존한다. 전장 렌더·시야/탐지·고지대 보조 시야·충돌·작업·공격·적 대상에서 제외한다. 아군에게만 수송선별 목록을 보낸다. 수송 중 부대를 선택하면 부모 수송선을 강조하고 수송선으로 선택을 옮길 수 있다.
- 이동 후 유효 지형에 순차 하차한다. 대열에 따른 하차 위치를 계획하고, 복수 수송선의 중심을 나누며, 실제 도착 시 지상 병력과 건물을 피해 빈 위치를 확인한다. 물/불가 지형은 가장 가까운 사용 가능한 지형을 찾아 수송선이 이동한다. 공간이 막히면 병력을 보존해 재시도한다. 하차한 유닛은 기존 그룹·대열·태세를 유지하고 경계한다.
- 원작 자료로 확정한 값은 비용·능력치·공간·이동 속도다. 현재 수송 접근 여유 1타일, 하차 탐색 반경 2타일, 하차 간격 8틱은 이 엔진의 결정적 조작 규칙이며 원작 애니메이션 프레임을 완전히 재현했다는 주장은 하지 않는다.
- 여러 초상화의 개별 하차 지시를 순서대로 보관한다. 수송선 파괴 시 탑승 병력·인구·부대·작업 참조를 함께 제거한다. 접근 중이던 병력은 정지하고 살아남는다. 이미 날아온 투사체는 탑승한 대상을 잃으면 소멸하며 병력 내부에 피해를 주지 않는다.
- 레어 변태 중 라바·자원 반납·본부 생존을 유지한다. 중복 결제를 막고 취소는 75% 환불, 파괴는 변태 비용을 돌려주지 않는다. 완료 시 기존 피해량과 체력 소수부를 보존하며 레어의 최대 체력·생산/선행 조건을 적용한다.
- 수송 중 병력·접근/하차 대기·변태·미래 명령을 저장한다. 이전 6~10 형식의 엔진·원본 데이터 버전·체크섬을 검증해 11로 이관한다. 6A 원문은 최초 교체 전에 `.stage6a-backup`에 보관하고 백업 실패 시 덮어쓰지 않는다. 특수 연습 저장 키는 기존 네 모드와 분리한다.

수송/탐지/생산/변태/저장 결정성의 엔진 테스트와 전체 회귀, 두 세로 화면 크기의 실제 터치·Worker·Pixi 검증을 실행한다. 실제 Android/iOS·물리 GPU 인증과 구별한다. 배포 SHA·CI·증빙은 별도 검증 영수증에 기록한다.
