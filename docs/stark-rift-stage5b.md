# 단계 5B: 원거리 무기와 지속 투사체

2026-11-12. 단계 5A에 이어 벌처·탱크(탱크 모드)·히드라리스크·드라군의 기본 무기를 연결한다. 단계 5 전체의 시야·승패·AI 완료를 의미하지 않는다.

## 구현

- BWAPI v4.4.0의 Fragmentation Grenade 20/30프레임/160px/Concussive, Arclite Cannon 30/37프레임/224px/Explosive, Needle Spines 10/15프레임/128px/Explosive, Phase Disruptor 20/30프레임/128px/Explosive를 추출한다. 값은 피해/공격 간격/사거리 순서다. 네 무기의 Normal 폭발 유형도 추출하여 탱크 모드에 공성 모드의 범위 피해를 섞지 않는다.
- 벌처·탱크는 지상만, 히드라·드라군은 지상과 공중을 공격한다. 드라군은 기존 프로토스 지상 무기 연구를 반영한다. 테란 차량·저그 원거리 연구 UI는 콘텐츠 단계의 확장 대상이며 현재 연구를 허위 적용하지 않는다.
- 유탄·플라스마는 발사한 틱에 피해를 주지 않는다. 정수 20Hz 이동, 속도 나머지, 발사 시 확정한 피해와 타격 수, 소유자·발사자·표적 ID, 생성/만료 틱을 저장한다. 발사자가 죽거나 새 이동/정지 명령을 받아도 발사한 탄은 지속한다. 표적 사망·유효하지 않은 대상 층·같은 소유자로 변경된 대상에는 피해를 주지 않고 소멸한다. 표적 추적은 내부 시뮬레이션에서 수행한다.
- 비행 속도는 `combat/mechanics.ts`에 명시한 Stark Rift용 값이다(유탄 384px/s, 플라스마 240px/s). 이는 원본 프레임 애니메이션·가속도·투사체 속도의 완전 재현을 주장하는 수치가 아니다. 포격·가시 공격은 직접 명중 효과로 처리한다. 발사 애니메이션의 원본 damage-point·가속도 재현은 별도 작업이다.
- 발사된 탄은 최대 200틱(10초)에 소멸하며 최대 4096개로 제한한다. 한도 도달 시 새 발사를 보류하고 공격 재사용 시간을 소비하지 않는다. 기존 탄의 명중과 새 즉시 타격을 모은 뒤 피해를 적용하여 같은 틱 공격의 순서 의존을 줄인다.
- 방어력·크기 배율은 명중 시 표적 상태로 계산한다. 보호막 초과 피해·최소 0.5 체력 피해와 1/256 잔여값, 기존 사망·인구·자원/건설 참조 정리를 유지한다.
- 렌더러에는 현재 보이는 탄의 ID·소유자·무기·현재 좌표만 보낸다. 숨겨진 표적 ID·목표 좌표·발사자 ID는 전달하지 않는다. 보간 위치도 현재 시야를 다시 확인한다. 유탄·플라스마 그래픽과 무기별 명중 효과는 기존 임시 벡터 아트에 통합한다.

## 큰 유닛 접근 경로 보완

경로 탐색은 점유된 적 중심 대신 접근 가능한 경로 끝을 반환한다. 기존 이동 코드가 이 경로 끝을 적의 마지막 위치로 오인하면 큰 반경의 벌처·드라군은 매 틱 경로를 취소할 수 있었다. `MovementState.trackedTarget`에 마지막으로 경로를 계획한 표적 위치를 별도로 저장한다. 실제 표적이 한 타일 이상 움직이거나 접근을 마쳤을 때 재탐색하며, 경로 끝 자체의 보정으로 취소하지 않는다. 시야 소실 시 이 마지막 확인 위치를 사용한다. 지도 경계와 저장 복원도 함께 검사한다.

## 사이트에서 확인

기존 `/stark-rift-dev`에 `원거리 연습`을 추가한다. 테란은 벌처 2기(부대 1)·탱크 1기(부대 2), 저그는 히드라 3기, 프로토스는 드라군 2기로 시작한다. 부대를 선택하고 `공격 이동` 후 적 근처를 터치한다. 저그/프로토스 연습에는 공중 오버로드 표적이 있다. 기존 `기지 운영`, `전투 연습`을 유지하고 새 모드의 저장 키 `paperoid.stark-rift.development.v1.ranged.<race>`를 분리한다. 테란의 혼합 선택은 `혼합 병력`으로 표시한다. 오버로드는 비무장으로 안내한다.

## 저장과 검증

엔진 `0.9.0-stage5b`, 스키마/형식 8, Worker 프로토콜 9. 형식 6(단계 4)과 7(단계 5A)은 원문 체크섬·버전·이전 전투 규칙 해시를 확인한 뒤 변환한다. 이전 이동 상태에 표적 추적 좌표를 보충하고 기존 5A 전투에는 빈 비행 목록을 추가한다. 읽는 동안 원문을 덮어쓰지 않는다. 첫 교체 전에 형식 6은 `.stage4-backup`, 형식 7은 `.stage5a-backup`에 원문을 보존한다. 백업 실패 시 기존 기록을 교체하지 않는다.

자동 검증은 새 무기 원본값·대상 층·피해 배율·발사와 명중의 시간 차이·발사자/표적 사망·보호막·연구·비행 저장/결정적 재실행·비행 수/시간 상한·시야 정보 최소화·이전 저장 백업과 세 종족의 연습 표적 처치를 다룬다. `ranged-smoke.py`는 production Worker의 터치 조작으로 세 종족×두 세로 화면에서 모든 새 무기의 발사, 실제 비행, 지상/공중 처치, 운영 기록 보존, 별도 저장 복원, 가로 차단을 검사한다. `combat-smoke.py`, `touch-build-smoke.py`와 전체 회귀도 유지한다. 실기기·실제 GPU 검증과 원본 전투 애니메이션 재현을 대신하는 검증은 아니다.

다음 단계는 탐색/기억 안개·고지대/탐지, 경기 승패, 특수 전투와 재생·순찰 교전 정책이며 전체 콘텐츠·상대 AI·최종 아트는 후속 단계다.
