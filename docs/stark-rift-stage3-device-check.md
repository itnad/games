# 3단계 내부 검증 화면과 성능 측정

2026-11-03. 엔진 0.6.2-stage3. 이번 작업은 개발 검증 도구이며 공개 게임 기능 추가가 아니다.

## 실행

```sh
npm run dev:stark-rift-lab
```

같은 컴퓨터의 브라우저에서 `http://127.0.0.1:4174`를 연다. 별도 Vite 루트인 `tools/stark-rift-lab`만 사용하며, Paperoid의 공개 `app` 라우트·메인 게임 목록에는 연결하지 않는다. 테스트 개체는 합성 수치이며 원작 데이터나 경제·전투 구현으로 취급하지 않는다. 검증용 전맵 가시성도 실제 시야 규칙이 아니다.

휴대폰에서 확인할 때는 개발자가 실행하는 컴퓨터와 같은 네트워크를 사용한다.

```sh
npm run dev:stark-rift-lab -- --host 0.0.0.0
```

휴대폰에서 해당 컴퓨터의 LAN 주소와 포트 4174로 접속한다. 개발 서버의 호스트 설정은 이 명령에서만 바뀌며 기본값은 127.0.0.1이다. 휴대폰 접근·브라우저 실행은 이번 클라우드 작업에서 확인하지 않았다.

```sh
npm run build:stark-rift-lab
npm run bench:stark-rift
```

첫 명령은 타입 검사 후 `work/stark-rift-lab/dist`에 별도 검증 번들을 생성한다. 이 폴더는 Git에서 제외되며 Sites의 공개 배포 산출물에 넣지 않는다. 두 번째 명령은 서버(Node) 측정을 실행하고 `work/stark-rift-lab/benchmark.json`에 환경·소스 식별자·측정 결과를 기록한다. Git 식별자를 읽지 못하면 `null`로 표시하며 임의의 커밋으로 채우지 않는다.

## 검증 시나리오

| 시나리오 | 목적 |
| --- | --- |
| 선택·슬롯·명령 | 전투 유닛 10, 일꾼 4, 적 2로 개별·그룹 선택과 직접 대상 지정 확인 |
| 50기 좁은 통로 | 기존 자동 검사와 같은 1타일 통로, 5개 부대의 연합 이동 확인 |
| 50기 균열 분지 | 실제 96×96 지도의 본진·경사로·균열을 포함한 장거리 이동 확인 |
| 200기 교차 이동 | 양쪽 100기의 교차 교통과 탐색 대기 확인; 교전은 수행하지 않음 |

시나리오는 일시정지 상태로 연다. `시나리오 이동`은 플레이어의 전체 테스트 병력을 정해진 목적지로 보낸다. 200기 시나리오의 적 이동은 테스트용 AI 명령이다. `초기화`는 선택한 시나리오를 새로 연다.

## 실제 기기 확인 순서

Android Chrome과 iOS Safari에서 각각 기기 모델·OS·브라우저 버전을 메모한다. 가로 회전과 작은 세로 화면도 별도로 확인한다.

1. 개별 터치, 300ms 길게 눌러 그룹 선택, 일꾼 작업반, 적 직접 지정을 확인한다.
2. 슬롯 가로 훑기로 연합 선택, 슬롯에서 전장으로 위쪽 스와이프, 슬롯 두 번 터치 카메라 이동을 확인한다. 스와이프 중 브라우저 스크롤이나 원치 않는 명령이 나오는지도 기록한다.
3. 빈 땅 짧은 터치는 이동, 드래그는 카메라 이동, 두 손가락은 확대만 수행하는지 확인한다. 손가락 하나를 먼저 놓거나 터치를 취소해도 명령이 새로 발생하지 않아야 한다.
4. 전열·종대·분산, 정지·사수·순찰을 확인하고, 태세 변경을 반복해도 이동이 이어지는지 확인한다.
5. 50기 통로에서 전원 통과·도착과 겹침을 확인한다. 실제 지도·200기 교차 이동에서는 멈춘 유닛과 재탐색 반복도 관찰한다.
6. 이동 중 `저장` 후 다른 명령을 내리고 `복원`한다. 일시정지 상태로 돌아오며 선택·슬롯·다음 명령 대상이 저장 시점과 일치해야 한다. 이 화면의 복구본은 메모리에만 있으므로 창을 닫은 뒤 영구 이어하기를 검사하는 기능은 아니다.
7. 다른 앱으로 전환 후 돌아온다. 자동으로 진행되지 않고 명시적인 `이어서 진행`을 통해 재개되는지 확인한다.
8. 10분 이상 이동을 반복한다. 패널을 닫아 실제 전장을 조작하고, 다시 열어 측정값과 메모를 확인한다. Chrome Performance/메모리 도구 또는 Safari Web Inspector에서 GPU·Worker·전체 메모리를 별도로 확인한다.

`측정·확인` 패널의 항목은 처음에 모두 `미확인`이다. 직접 확인한 항목만 통과/실패로 표시하고 `검증 기록 JSON 저장`으로 내보낸다. 시나리오를 바꾸거나 초기화하기 전에 내보낸다. 자동으로 실제 기기 심사를 통과 처리하지 않는다.

## 측정 해석

- 전체 틱은 원래 엔진의 틱 복사·명령·시스템·최종 런타임 검증을 포함한다. 시스템별 시간은 경로 탐색/이동 등의 실행 시간이다. GPU와 Worker 메시지 전송은 포함하지 않는다.
- 시간·통계는 `SimulationState`와 저장 체크섬에 넣지 않는다. 기본 프로덕션 Worker는 프로파일링과 테스트 지도 주입을 사용하지 않는다. 실험실 전용 Worker의 별도 MessagePort로만 측정값을 전달하며 기존 게임 메시지 규약을 확장하지 않았다.
- Worker 표는 최근 200틱의 평균·nearest-rank p95·최댓값이다. 복원할 때 창을 초기화한다. rAF 간격은 최근 600개이며 숨긴 탭의 간격을 제외한다. rAF 간격은 GPU 실행 시간이 아니다.
- 브라우저 JSON에는 세션 최고 지연과 5초 간격 기록을 최대 720개(약 1시간), 최근 이벤트 200개까지 담는다. 장시간 변화 확인에 사용하며 무한히 메모리에 쌓지 않는다.
- 메인 JS 힙은 지원하는 브라우저에서만 표시한다. GPU·Worker 메모리를 포함하지 않으며 미지원은 `null`로 기록한다.
- Node 측정은 첫 20틱과 이후 구간을 분리한다. `sampleChecksPassed`는 20틱 간격의 겹침 검사와 탐색 개수 예산 검사 결과이며 전체 경기 정확성의 보증이 아니다. 통로 전원 도착만 별도의 완료 기준으로 검사한다. 다른 시나리오의 남은 명령 수와 상태도 별도로 기록한다.
- 계획의 목표는 틱 평균 6ms·p95 10ms 이하, 경로 탐색 평균 2.5ms 이하이다. 서버 수치 통과도 모바일 수치 통과를 뜻하지 않는다. 시간 초과 결과는 숨기지 않으며, CLI의 오류 코드는 표본 검사/필수 도착 실패에만 사용한다.

## 이번 자동 검증과 판정

전용 테스트 196개, 타입 검사, 별도 검증 화면 빌드와 실제 별도 스레드의 검증용 Worker 통신을 확인했다. 프로파일링을 켜고 끈 엔진의 매 틱 체크섬이 일치하고, 관측 콜백 오류가 경기를 중단하지 않는 것도 검사했다.

첫 측정 환경은 Linux x64, Node 24.19.0, AMD EPYC 9V74, 논리 CPU 3개인 클라우드 환경이다. 첫 20틱을 제외한 대략적 결과는 다음과 같다. 원본 JSON에는 환경·소스가 함께 기록되며, 매 실행 수치는 변동할 수 있다.

| 시나리오 | 틱 평균 ms | 틱 p95 ms | 경로 평균 ms | 측정 종료 때 남은 명령 |
| --- | ---: | ---: | ---: | ---: |
| 선택·명령 | 0.62 | 1.12 | 0.05 | 0 |
| 50기 통로 | 0.90 | 4.13 | 0.12 | 0 |
| 50기 실제 지도 | 27.33 | 63.36 | 1.21 | 4 |
| 200기 교차 | 15.40 | 28.60 | 6.16 | 80 |

50기 실제 지도에서는 이동 시스템 평균 약 21.74ms, 200기 교차에서는 이동 약 6.72ms·탐색 약 6.16ms였다. 측정 종료 시 남은 명령을 전원 도착으로 해석하지 않는다. 실제 지도는 1,200틱(게임 시간 60초), 교차 시나리오는 600틱(30초)만 측정했으므로 장기 교착 여부는 별도 조사 대상이다.

**실제 지도와 200기 시나리오가 성능 목표를 넘었으므로 3단계 완료는 계속 보류한다.** 다음 보완은 실제 지도에서의 경로 중간 지점 생략/구간 충돌 검사 비용, 대규모 교통의 재탐색 비용과 남은 명령의 원인을 조사하는 것이다. 최적화 전후 체크섬과 안전성 회귀를 유지해야 한다.

실제 모바일 GPU·터치 검증은 실행하지 않았다. 선택된 환경에 브라우저 제어 도구가 없고 Sites의 `site-workflow.mjs`/`build-site.mjs`도 없어 배포·Sites 소스 동기화 역시 미완료다. 기존 공개 버전 227을 최신 코드의 배포 결과로 표시하지 않는다.


## 후속 성능 최적화

이 문서의 표는 최초 측정 기록이다. 이후 최적화의 전후 수치와 203개 테스트·3,200틱 상태 비교 결과는 [성능 최적화 기록](stark-rift-stage3-performance.md)을 따른다. 실제 모바일 심사는 계속 미확인 상태다.


## 복사·검증 계측 및 장시간 이동 검사 추가

내부 화면에서 상태 복사·최종 검증 시간을 별도로 볼 수 있다. Node 벤치마크는 두 장시간 이동 검사도 실행하고 보고서에 traffic을 기록한다. 최신 214개 테스트·서버 시간 예산·전원 도착 결과와 실제 기기 확인의 경계는 [2차 성능 기록](stark-rift-stage3-performance-2.md)을 따른다.
