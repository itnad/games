# 단계 3 전 추가 신뢰성 점검

2026-11-02, 엔진 `0.5.1-prestage3`. 스키마/저장 4, 통신 5 유지.

## 재현하거나 코드 경로로 확인하고 보완한 문제

| 문제 | 조치 | 검증 |
|---|---|---|
| 죽은 Worker에 저장본을 보내 복구가 진행되지 않음 | 복구 버튼은 이전 연결을 정리하고 새 Worker를 초기화한 뒤 복원. 복원 완료 전 새 경기의 초기 프레임은 표시하지 않음 | 실제 Worker 강제 종료 후 새 Worker에 체크포인트 복원·재개 |
| 무응답/잘못된 응답이 화면에 전달되지 않거나 버퍼 수신이 멈춤 | 초기 응답·heartbeat의 2.5초 제한, 오류 통지·리스너 해제·종료. 백그라운드 전환에서는 미응답 시간을 초기화 | 응답 없음/손상 패킷/error/messageerror/전송 예외 테스트 |
| 전송 실패 시 dispose도 예외가 나며 연결이 남음 | 오류·dispose에서 정리를 한 번만 수행. disposed 수신도 최종 상태로 처리 | postMessage 예외 및 반복 dispose 테스트 |
| 동일 틱 패킷이 보간을 반복 초기화함 | 같은/이전 틱은 표시하지 않고 버퍼는 반환. 복원 메시지에서 틱 기준 초기화 | 동일 틱·복원 뒤 낮은 틱 수신 테스트 |
| 외부 저장 소비자가 유일한 정상 체크포인트를 변경할 수 있음 | 검증 후 내부 복사본 보관, 조회·외부 콜백에도 독립 복사본 전달 | 입력과 반환 복사본 변조 후 복구본의 체크섬 유지 |
| 비동기 외부 저장 실패가 처리되지 않음 | 동기 예외·Promise 거부 처리, 현재 창의 복구본 유지, 외부 저장 실패 상태 표시. 오래된 저장 결과가 새 저장 상태를 덮지 않음 | 복사본 격리 테스트 및 내부 화면 번들 검사. React 화면 상호작용은 브라우저에서 추가 확인 필요 |
| 추적 대상 삭제 뒤 idle 이동에 이전 목적지·나머지가 남아 다음 틱이 실패 | 전체 이동 상태를 idle 기본값으로 초기화 | focusAttack 대상 삭제 후 다음 틱 정상 진행 |
| 초기화 중 화면 해제/두 번째 GPU 초기화 실패에서 자원이 남음 | 초기화 완료/실패 뒤 한 번만 자원 정리. 임시 지형·앱·텍스처·ticker·observer·리스너 해제. 화면 설정 실패도 renderer 정리 | 모의 자원으로 초기화 대기 중 종료/두 번째 앱 초기화 실패 재현 |

## 검증 범위와 단계 3 진입

- `npm test`: 전체 빌드, 기존 게임·한국어 조사 회귀, 전용 타입·테스트.
- 내부 `SimulationSession` 별도 Vite 빌드: Worker 자산과 Pixi 동적 import 생성 확인.
- 이전 단계의 10,000틱 결정성과 저장·복원 테스트 유지.
- 이제 선택·부대·경로 탐색을 구현할 연결 기반은 마련됐다. 실제 히트 영역/선택 규칙/경로 탐색/충돌/대열과 콘텐츠는 단계 3 이후 작업이다.
- 실제 모바일 GPU·터치·메모리 성능과 React 화면의 종합 상호작용은 아직 검증하지 않았다. 모의 자원 수명주기 검사는 GPU 동작 보증이 아니다.
- 복구본은 현재 창의 메모리에 보관한다. 앱 종료까지 보존하는 IndexedDB 영속 저장은 여전히 후속 작업이다.
- 새 결함이 없음을 보증하는 검토가 아니다. 단계 3 구현 중에도 명령·상태·저장·입력의 회귀 검증을 유지한다.
