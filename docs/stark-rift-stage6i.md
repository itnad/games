# 단계 6I · 최대 에너지 연구

2026-11-15. 엔진 `0.19.0-stage6i`, 저장·스키마18, 통신19. 세로 플레이 전용.

## 연구와 에너지

| 연구 | 대상 | 연구시설 | 미네랄/가스 | 경제 시간 |
| --- | --- | --- | --- | --- |
| 뫼비우스 반응로 | 고스트 | 연결된 코버트 옵스 | 150/150 | 52.1초 |
| 아폴로 반응로 | 레이스 | 연결된 컨트롤 타워 | 200/200 | 52.1초 |
| 카이다린 코어 | 아비터 | 동력 있는 아비터 트리뷰널 | 150/150 | 52.1초 |

원작2500프레임에 기존 경제 시간 반감을 적용한1042틱이다. 각 연구는1회만 가능하며, 중복·같은 시설의 생산/연구 충돌·자원·동력·애드온 연결을 기존 연구 시스템에서 검사한다. 동력이나 부모 건물이 없으면 진행을 멈춘다. 취소는 현재 게임의 연구 전액 환불 규칙을 유지한다.

연구 완료 후 해당 플레이어·해당 유닛 종류의 최대 에너지가200에서250으로 바뀐다. 기존 유닛의 현재 에너지는 그대로이며 이후 원래 회복 속도로250까지 차오른다. 은폐 중의 고스트·레이스는 원래 지속 소모를 유지하며 회복하지 않는다. 연구 전 생산한 유닛·정지된 아비터·수송 중인 고스트도 완료된 연구의 최대치를 적용한다.

연구 후 실제 생성되는 유닛은 새 최대치의1/4인62.5(고정 소수점16000)로 시작한다. 연구 전에는50이다. 이미 대기열에서 생산 중인 유닛도 생성 시점의 완료된 연구를 따른다. 화면 에너지는 기존과 같이 정수로 버림 표시하므로 처음에는62/250으로 보일 수 있다. 비용·회복·은폐 소모·기존 주문은1/256 단위를 유지한다. 연구는 주문 비용·회복 속도·은폐장 범위를 바꾸지 않는다.

## 확인 방법

`/stark-rift-dev` → 테란 또는 프로토스 → 특수 연습 → 새 테스트 시작. **해당 연구소 선택 → 연구**. 연습에서는 연구시설과 추가 미네랄600·가스650을 명시적으로 제공한다. 연구를 미리 완료하거나 현재 에너지를 채우지 않는다. 기존 특수 연습의 고스트·레이스50, 아비터200과 기존 연구·부대·수송 대상은 유지한다. 일반 운영에서는 시설 건설과 모든 비용을 직접 충족해야 한다.

자기 유닛·현재 보이는 적의 에너지 바, 선택 정보, 수송 초상화와 상세 정보에 실제200/250 최대치를 표시한다. 적의 연구 목록은 보내지 않는다. 잘못된 최대치·최대치를 넘는 표시 값·에너지/최대치 한쪽만 있는 패킷을 거절한다.

## 저장과 검증 경계

저장6~17의 원본 버전·해시·체크섬을 검증해18로 이관한다. 기존 연구 해시를 별도 상수로 고정해 이전 데이터도 검증한다. 단계6H 저장의 자동시전·부대 설정·수동 유예·리콜·스테이시스·에너지 분수·자원·화물·RNG·대기 명령을 보존한다. 이전 저장에 신규 연구나200초과 에너지를 끼워 넣은 자료는 거절한다. 덮어쓰기 전 원문을 `.stage6h-backup`에 보관하며 백업 실패 시 원문을 교체하지 않는다.

`data/energy-original.json`은 BWAPI v4.4.0 UpgradeType.cpp와 고정 OpenBW 커밋의 `unit_max_energy`·초기 에너지 설정에서 추출한다. 이전 원작 JSON은 수정하지 않는다. `python tools/stark-rift-data/extract-energy.py <원본 폴더>`로 재생성한다.

엔진 검증은 비용·중복·취소·정확한 완료, 동력/애드온 중단, 기존/새 생산 초기값, 플레이어/유닛 분리,250 회복 상한, 은폐 소모·수송·정지·표시 검증과 저장 결정성/이관을 포함한다. 브라우저 검증은 실제 연구·저장/재접속·표시와 기존 주문을 정상 시간으로 확인한다. 실제 Android/iOS·하드웨어 GPU 인증은 별도다. 추가 유닛·주문, 메딕/스팀팩·스톰, 적 전략 AI와 최종 미술은 후속 범위다.
