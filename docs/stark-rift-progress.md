## 단계 1 — 결정적 엔진 기반

구현일: 2026-11-01. 엔진 `0.3.0-stage1`, 스키마·저장·통신 버전 3.

### 구현한 내용

- `fixed-point.ts`: 1타일=256, 20Hz/50ms 상수, 안전 정수 덧셈, BigInt 중간 곱셈과 0 방향 나눗셈, 부호 있는 이동 나머지 누적. 음수 0을 정규화한다.

- `checksum.ts`: 키 순서에 의존하지 않는 정수 JSON 직렬화와 UTF-8 xxHash32. 공식적으로 알려진 짧은 입력·16바이트 이상 입력의 벡터를 검사한다.
- `state.ts`: 실행 중 상태 저장·복원, 독립된 복사본 생성, 전체 경기 상태 체크섬 검증, 버전·소유자·카운터·예약 명령·난수 스트림의 일관성 검사. 카메라·선택·저장 시각은 경기 체크섬에서 제외한다.

### 현재 경계와 다음 단계

단계 2는 지도 데이터, PixiJS 렌더러, 카메라·미니맵·시야 텍스처와 1:2:1 UI 골격이다. 이후 단계에서 선택·경로 탐색·경제·전투·AI를 순서대로 연결한다.

- 실제 게임 명령은 관련 단계의 핸들러가 등록되기 전까지 거부한다. 엔진이 실행하지 않은 명령을 성공으로 처리하지 않는다.
- 투사체·효과·예약 이벤트·AI 저장소는 아직 빈 계약이다. 관련 단계에서 스키마와 호환 버전을 함께 확장한다.
- 초기 엔티티 저장소는 JSON으로 직접 보존 가능한 정렬된 compact SoA 배열이다. TypedArray 용량 풀과 희소 컴포넌트는 실제 렌더/전투 부하를 측정할 때 도입한다.
- 원작 수치 데이터 번들과 해시는 콘텐츠 단계에서 생성한다. 현재 `stage1-unbuilt` 표시는 게임 콘텐츠가 아직 없다는 뜻이며 기획 수치를 임의로 만들지 않는다.
- 실제 Worker 실행 어댑터·백그라운드 처리·IndexedDB·리플레이 UI는 아직 구현하지 않았다.
