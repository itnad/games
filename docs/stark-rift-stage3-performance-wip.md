# 3단계 성능 최적화 — 실행 중단 당시의 중간 기록

2026-11-03. 기준 GitHub 커밋: a134c98d21d3f63b4eed710a42ada83a0e979701.
이 브랜치는 실행 환경 연결 중단으로 검증을 마치지 못한 작업 백업이다. main에 병합하거나 배포한 완료본이 아니다.

## 변경 내용

- 원/타일 구간 판정에서 안전한 정수 연산으로 같은 결과를 낼 수 있는 경우 BigInt 비용을 줄인다. 범위를 넘으면 기존의 정확한 BigInt 판정으로 돌아간다.
- 타일이 이동 선분의 지지 직선에서 반경보다 멀리 떨어져 있으면 복잡한 교차 검사 전에 제외한다.
- 공간 해시에서 구간의 후보를 조회한다. 많은 빈 버킷에 걸치는 긴 구간은 ID 순서의 전체 조회로 전환한다.
- 명령/탐색/이동 실행 구간에서만 막힌 타일의 행별 목록을 사용한다. 기본 NavigationGrid는 기존처럼 지도 변경을 즉시 관찰한다.
- 이동에서는 공간 해시를 갱신하며 공유하고, 같은 개체의 중간 지점 생략 직후 같은 구간을 다시 검사하지 않는다.
- 목적지 예약도 공간 버킷으로 좁혀 확인한다. 층과 반경/진입 여유의 규칙은 유지한다.
- 마지막 변경은 경로 탐색 실행 구간 안에서 같은 격자 중심의 clear 결과를 재사용한다. 다음 탐색 실행에서는 새 캐시를 만든다. 이동/명령 구간에서는 이 정적 장애물 캐시를 사용하지 않는다. 캐시는 SimulationState나 저장 형식에 넣지 않는다.

## 실제로 확인된 범위

초기 최적화(행별 지형 목록·긴 구간 전환·격자 캐시를 넣기 전)는 타입 검사와 기존/새 테스트 201개를 통과했다. 같은 초기 변경에서 4개 벤치마크 시나리오의 최종 전체 상태 체크섬이 기준 커밋의 결과와 일치했다.

추가 변경 중간 측정에서는 첫 20틱을 제외한 결과가 아래와 같았다. 이 수치는 **마지막 격자 clear 캐시를 넣기 전**의 결과이므로 이 브랜치 전체의 검증 수치로 사용하면 안 된다.

| 시나리오 | 틱 평균 ms | p95 ms | 탐색 평균 ms | 남은 명령 |
| --- | ---: | ---: | ---: | ---: |
| 선택/명령 | 0.61 | 1.05 | 0.05 | 0 |
| 50기 통로 | 1.12 | 5.63 | 0.16 | 0 |
| 50기 실제 지도 | 10.09 | 21.83 | 0.39 | 4 |
| 200기 교차 | 16.68 | 34.90 | 5.86 | 80 |

실제 지도와 200기는 여전히 틱 평균 6ms/p95 10ms, 탐색 평균 2.5ms 목표를 만족하지 못했다. 긴 구간에서 공간 해시가 느려지는 것도 확인해 후보 조회 방식에 전환 기준을 넣었다.

연결 중단 뒤 코드 변경 기록과 기준 GitHub 파일로 복구한 순수 기하 함수만 JavaScript 도구 실행기에서 비교했다. 지도 범위의 무작위 20,000개 입력에서 원 판정과 타일 판정 각각 기준 구현과 일치했다. 이것은 엔진 전체·타입 검사·빌드·실제 기기 검증을 대신하지 않는다.

## 연결 중단과 복구

CPU 프로파일을 수집하던 중 실행 명령이 exec-server 연결 중단 오류를 반환했다. 환경 상태 도구도 connectivity=offline으로 보고했다. 원인은 확인되지 않았다.

이 브랜치의 파일은 기준 커밋의 내용에 도구 호출에 남은 변경을 재적용해 보관했다. 중단 직전 캐시 추가와 최종 코드 전체는 실행 환경에서 확인하지 못했다. 실행 환경의 파일 보존 여부도 아직 확인하지 못했다. 마지막 완료본은 main의 기준 커밋에 유지했다.

## 재개할 작업

1. 실행 환경을 다시 연결한 뒤 현재 작업 파일과 이 브랜치의 파일을 대조한다.
2. 격자 캐시와 행별 지형 목록을 켠 검사 결과를 전체 순회 기준 구현과 대조한다. 새 틱/지도 변경, 도착 후 정지 개체, 제외 ID, 지상/공중, 접선, 큰 반경을 포함한다.
3. npm run test:stark-rift, npm test, npm run build:stark-rift-lab을 통과시킨다.
4. npm run bench:stark-rift로 완성 후보를 측정한다. baseline과 후보의 매 틱 체크섬을 비교한다. 현재 확인한 최종 체크섬 일치만으로 매 틱 동등성을 주장하지 않는다.
5. CPU 프로파일로 실제 지도 이동 비용과 교차 200기 탐색 비용을 더 줄인다. 목표 초과와 남은 명령을 숨기지 않는다.
6. 검증이 끝난 코드만 main에 반영한다. 실제 모바일 GPU/터치와 Sites 배포 도구 부재는 별도로 남아 있다.

저장/스키마 5와 통신 6을 바꾸지 않았다. 엔진 버전도 현재는 0.6.2-stage3을 유지한다. 동일한 정수 판정과 상태 전개를 확인하는 것이 목표이며, 결과가 달라지는 변경이 필요하면 버전과 저장 호환성 검토를 함께 진행해야 한다.
