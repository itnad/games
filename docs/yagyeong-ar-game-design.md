# 야경단 AR 게임 기획서

> 상태: 1차 기획 (취미 인디 규모, 코드 없음)  
> 최종 갱신: 2026-11-12  
> 저장소: `itnad/games`

## 0. 한 줄 요약

**폰을 들면 그 자리가 전장이 된다. 등롱이 비추는 곳에만 악귀가 보이고, 뒤에서 나는 소리에 돌아보고, 숙여서 피하고, 조준해서 쏘고, 부적으로 봉인하는 1~2분짜리 제자리 AR 퇴마 런.**

- 혼자서 몇 주 안에 0단계 프로토타입을 만들 수 있는 규모로 잡는다.
- 위치기반 이동, 분대 실시간 전투, 스마트글라스는 이 문서의 범위가 아니다. 재미가 검증된 뒤의 확장 후보로 부록 A에만 적는다.
- 테마는 한국 설화 악귀를 유쾌하게 퇴치하는 야경단(夜警團)이다.

## 1. 프로젝트 원칙

- 게임명은 가제 `야경단`, 영문 표기는 `Yagyeong`이다. 공개 경로는 `/yagyeong`으로 예약한다.
- `itnad/games` 저장소의 Paperoid 프로젝트 안에서 만든다. 완성 기준을 통과하기 전까지 Paperoid 메인, 전체 게임 목록, 빠른 시작에 노출하지 않는다.
- **폰 브라우저만** 지원한다. 카메라, 자이로, 가속도, 진동, 소리는 모두 브라우저 API로 처리한다. 네이티브 앱, WebXR, 외부 기기는 쓰지 않는다.
- **운영비 0원 원칙**: 서버는 기존 Cloudflare Workers + D1에 점수판과 일일 시드만 둔다. 실시간 동기화, 지도 데이터, 사용자 신고 처리처럼 사람이 계속 봐야 하는 운영 요소는 넣지 않는다.
- **제자리 플레이**: 플레이어는 걷지 않는다. 몸을 돌리고 숙이는 것이 전부다. 어디서든 1~2분이면 한 런이 끝난다.
- **AR을 끌 수 없다**: 몸을 돌려 조준하는 것이 유일한 기본 조작이다. 터치 드래그 조준은 접근성 설정에서만 켠다.
- 모바일 세로 화면만 지원한다. 가로 화면에서는 플레이를 막고 세로 전환 안내를 표시한다.
- 카메라 영상은 기기 밖으로 나가지 않는다. 서버는 런 결과만 받는다.
- 모든 한국어 동적 문구는 `app/korean-particles.js` 헬퍼를 사용한다(AGENTS.md 규칙).

## 3. 핵심 플레이 루프

1. **시작**: 폰을 세워 들면 카메라가 켜지고 3초 카운트 뒤 첫 방이 시작된다. 시작 전 "주변 1m가 비어 있는지 확인" 안내를 1회 보여준다.
2. **방**: 20~40초. 악귀 1~4마리가 플레이어 주위 2~10m 가상 반지름에 나타난다. 등롱 안에 들어온 악귀만 보이고, 등롱 밖 악귀는 소리와 진동으로만 존재를 알린다.
3. **정화**: 체력이 0이 된 악귀는 8초 동안 `정화 가능` 상태로 떠 있다. 조준한 채 길게 누르면 봉인되고 점수와 도감 기록이 생긴다. 정화하지 않으면 사라지고 점수는 절반이다.
4. **선택**: 방이 끝나면 부적 3개 중 1개를 고른다(로그라이크식 성장). 5초 안에 안 고르면 첫 번째가 자동 선택된다.
5. **보스**: 마지막 방은 지박령 1마리다. 60~90초.
6. **결과**: 점수, 정화 수, 숙이기 성공 수, 도감 신규 등록을 보여주고 `오늘의 순찰` 점수판에 반영한다.

한 런은 방 4개 + 보스로 **총 2~3분**을 목표로 한다. 팔을 들고 하는 놀이이므로 3분을 넘기지 않는다. 런 중 폰을 내려놓으면 일시정지되고, 60초 안에 다시 들면 이어진다.

## 4. 조작 체계 (세로 한 손)

| 입력 | 동작 |
| --- | --- |
| 폰 방향(자이로·지자기) | 조준. 화면 중앙에 고정 조준점이 있고 몸과 폰을 돌려 맞춘다 |
| 오른손 엄지 큰 버튼 탭 | 소금총 발사(단발). 길게 누르면 충전 사격 |
| 조준점 위 악귀를 길게 누르기 | 정화 |
| 왼손 엄지 버튼 1개 | 부적 사용(런 중 얻은 발동형 부적) |
| 폰을 빠르게 아래로 내리기 | 숙이기. 머리 높이 공격을 피한다 |
| 폰을 아래로 향한 채 1초 유지 | 재장전 |
| 폰을 세게 흔들기 | 긴급 결계(0.8초 무적, 런당 1회) |
| 화면 좌우 가장자리 화살표 + 상단 레이더 | 화면 밖 악귀 방향 안내 |

- 드래그 조준은 기본으로 제공하지 않는다. 접근성 설정의 `고정 자세 모드`에서만 켜고, 그때는 악귀 출현 범위를 전방 120도로 제한한다. 자이로가 없는 기기는 자동으로 이 모드가 된다.
- 조준 보정: 조준점 반경 안에 들어오면 약한 끌림을 준다. 자이로 드리프트는 런 시작 때 지자기로 기준을 잡고 30초마다 다시 맞춘다.
- 진동은 지원 기기(안드로이드)에서만 켠다. iOS는 소리와 화면 흔들림으로 대체한다.

## 5. 등롱과 시야 규칙

폰 화각 60~70도라는 한계를 규칙으로 바꾸는 장치다.

- 조준점 중심 약 40도 원뿔이 `등롱`이다. 등롱 안의 악귀는 또렷하게, 등롱 가장자리는 반투명하게, 등롱 밖은 보이지 않는다.
- 카메라 영상 위에 어두운 비네트를 얹어 등롱 밖이 어둡다는 느낌을 준다. 실제 카메라 밝기는 바꾸지 않는다.
- 등롱 밖 악귀는 **소리·진동·레이더 점**으로만 알 수 있다. 플레이어는 들리는 방향으로 몸을 돌려야 한다.
- 부적으로 등롱을 넓히거나(시야 부적) 등롱 밖 악귀를 잠깐 비추는(횃불 부적) 효과를 준다. 등롱은 성장 축이다.
- 은신형 악귀는 등롱 **가장자리**에서만 드러난다. 정면으로 보면 사라지므로 "곁눈으로 본다"는 설화적 연출이 된다.

## 6. 소리와 진동 설계

뒤가 보이지 않는 매체이므로 소리가 두 번째 화면이다.

- 모든 악귀는 등장·접근·공격 준비 소리를 갖고, 스테레오 패닝으로 방위를 표현한다. 이어폰 사용을 시작 화면에서 권장하되 강제하지 않는다.
- 공격 예고는 **최소 1.2초 전**에 소리로 나온다. 화면 밖에서 예고 없이 들어오는 피해는 설계상 없다.
- 머리 높이 공격(숙이기로 피하는 것)은 높은 음, 몸통 공격(조준 격파로 막는 것)은 낮은 음으로 구분한다.
- 진동 패턴은 피격, 명중, 정화 성공, 숙이기 성공 네 가지만 쓴다.
- 공포 연출 수위는 "으스스하지만 깜짝 놀래키지 않는다"로 고정한다. 갑작스런 큰 소리(점프 스케어)는 쓰지 않는다.

## 7. 악귀 설계

### 7.1 등급

| 등급 | 어디서 | 특징 |
| --- | --- | --- |
| 잡귀 | 일반 방 | 1~4마리, 단일 행동 유형 |
| 원귀 | 3방 이후 | 행동 유형 2개 조합, 약점 부위 |
| 지박령 | 보스 방 | 단계별 패턴 2~3개, 정화 성공 시 도감 특별 등록 |

### 7.2 행동 유형

AR에서 적은 "플레이어 기준 어디 있는가"가 전부다. 모든 행동은 **방위(수평각)·높이(수직각)·거리** 세 값의 변화로 정의한다.

| 유형 | 행동 | 대응 |
| --- | --- | --- |
| 급습형 | 등롱 밖에서 소리를 내며 빠르게 다가와 들이받는다 | 소리 방향으로 돌아 사격 |
| 포위형 | 2~3마리가 둘레를 돌며 번갈아 공격한다 | 레이더를 보며 우선순위 결정 |
| 은신형 | 등롱 가장자리에서만 보인다 | 곁눈으로 보며 사격 |
| 투사형 | 거리를 두고 화염을 던진다. 화염은 조준해 격파할 수 있다 | 조준 격파 또는 숙이기 |
| 저주형 | 공격 대신 조준 흔들림·화면 흐림을 건다 | 먼저 처리, 부정 씻기 부적 |

- 둠식 "적 조합이 만드는 압박"은 유형 2개를 한 방에 섞어서 만든다. 예: 투사형이 화염을 던지는 동안 급습형이 뒤에서 온다.
- 수직각은 -15도~+40도 안에서만 쓴다. 바닥이나 머리 바로 위를 보게 하지 않는다.
- 옆걸음 회피는 넣지 않는다. 자이로만으로는 몸의 이동을 알 수 없고, 서서 하는 놀이에서 위험하다. 회피는 **숙이기와 조준 격파** 두 가지다.

### 7.3 1차 도감 (8종)

달걀귀신(급습), 그슨대(포위, 어두울수록 커진다), 어둑시니(은신), 도깨비불(투사), 손말명(저주), 몽달귀신(급습+투사, 원귀), 물귀신(포위+저주, 원귀), 장산범(지박령, 소리를 흉내 내 반대 방향에서 나타난다).

특정 종교 의례를 직접 묘사하지 않는다.

## 8. 성장

### 8.1 런 안 (로그라이크)

방 사이에 부적 3개 중 1개를 고른다. 부적은 세 축이다.

- **소금총**: 산탄 폭, 충전 속도, 약점 피해
- **등롱**: 시야 각도, 은신 탐지, 횃불(등롱 밖 순간 노출)
- **몸**: 체력, 숙이기 판정 여유, 긴급 결계 추가 1회

발동형 부적(횃불, 부정 씻기, 소금 뿌리기)은 왼손 버튼에 1개만 장착된다.

### 8.2 런 밖 (메타)

- **도감 숙련**: 같은 악귀를 정화할 때마다 약점·소리 정보가 도감에 더 자세히 적힌다. 숙련 3단계부터 그 악귀의 약점이 등롱 안에서 자동 표시된다.
- **부적 해금**: 누적 정화 수로 부적 후보군이 늘어난다. 전투력이 영구히 오르는 요소는 없다. 성장은 "선택지가 넓어지는 것"이다.
- 외형(등롱 모양, 부적 그림, 정화 연출)은 도감 달성으로 연다. 유료화는 1차 범위에서 없다.

## 9. 오늘의 순찰

유일한 소셜 요소다. 해루질럿 일일 도전과 같은 규칙을 쓴다.

- KST 날짜마다 서버가 시드와 악귀 조합을 정한다. 클라이언트가 조건을 고를 수 없다.
- 모든 참가자가 같은 방 순서, 같은 악귀, 같은 부적 후보를 받는다.
- 무제한 재도전, 익명 참가자당 하루 최고 기록 1개.
- 일반 런 기록과 격리된다. 오늘의 순찰 결과는 도감에는 반영되지만 부적 해금 수에는 들어가지 않는다.
- 점수판은 상위 100명과 내 기록만 보여준다. 닉네임은 로컬에서 정하고 서버에는 익명 식별자와 닉네임만 저장한다.

## 10. 안전·개인정보

- **제자리 안내**: 런 시작 때 "주변 1m가 비어 있는지 확인하세요"를 보여준다. 매 런이 아니라 하루 첫 런과 설정 변경 시에만 반복한다.
- **이동 감지**: 가속도 센서로 걷는 패턴이 2초 이상 감지되면 런을 일시정지하고 "멈춰서 플레이하세요"를 띄운다. GPS는 쓰지 않는다.
- **카메라 영상**은 화면 합성에만 쓰고 전송·저장하지 않는다. 결과 화면 공유 이미지는 카메라 영상을 포함하지 않는다.
- 카메라 권한을 거부하면 어두운 단색 배경으로 같은 게임을 할 수 있어야 한다. 자이로 권한을 거부하면 고정 자세 모드가 된다.
- 위치 정보는 어떤 형태로도 수집하지 않는다.

## 11. 기술 설계

### 11.1 브라우저 API

| 기능 | 안드로이드 크롬 | iOS 사파리 | 대응 |
| --- | --- | --- | --- |
| 카메라 배경 | `getUserMedia` | `getUserMedia` | 720p 후면 카메라, `<video>` 위에 캔버스 |
| 방향 | `DeviceOrientation` | 사용자 제스처 뒤 권한 요청 | 시작 버튼 탭에서 권한 요청 |
| 숙이기·흔들기·걷기 감지 | `DeviceMotion` | 같은 권한 | 가속도 패턴 분류 |
| 진동 | `navigator.vibrate` | 불가 | 소리·화면 효과 대체 |
| 소리 | Web Audio 패너 | 같음 | 스테레오 패닝으로 방위 |
| PWA | 가능 | 가능 | 홈 화면 추가 안내 |

- AR은 "카메라 배경 + 자이로 방향 투영"(AR-lite)으로만 한다. 악귀는 플레이어를 원점으로 한 구면 좌표(방위·고도·거리)에 놓고, 폰 방향 벡터와 비교해 화면에 투영한다. 바닥 인식, 가림, 위치 추적은 하지 않는다.
- 렌더링은 캔버스 2D 스프라이트(8방향)에 거리별 크기·투명도를 적용한다. 해루질럿의 캔버스 유틸(`app/mudflat-canvas-utils.ts`)과 세로 터치 정책을 재사용한다. 3D는 쓰지 않는다.
- 60fps 목표, 중저가 안드로이드 30fps 보장. 런 밖(메뉴, 결과, 도감)에서는 카메라를 끈다.

### 11.2 결정성과 서버

- 악귀 출현, 이동, 부적 후보는 **시드 기반 결정적 RNG**로 만든다. 해루질럿의 저장된 런타임 RNG 규칙과 같다. 직접 `Math.random()`을 쓰지 않는다.
- 일반 런은 전부 클라이언트에서 판정하고 서버에 기록하지 않는다.
- 오늘의 순찰만 서버가 관여한다. 시드 발급(Workers), 결과 제출(D1), 점수판 조회. 결과 제출에는 시드와 입력 요약(발사 수, 명중 수, 숙이기 수, 방별 시간)을 함께 보내 명백한 조작(이론상 불가능한 수치)만 거른다. 정교한 치트 대응은 하지 않는다.

### 11.3 저장

| 저장소 | 내용 |
| --- | --- |
| 로컬 | 설정, 접근성 모드, 닉네임, 도감 숙련, 부적 해금, 진행 중 런(일시정지 복귀용) |
| D1 | 오늘의 순찰 시드 테이블, 참가자별 일일 최고 기록 |

도감과 해금이 로컬에만 있으므로 기기를 바꾸면 사라진다. 1차에서는 이를 받아들이고 설정에 "내보내기·가져오기(JSON)"만 둔다.

## 12. 화면 구성 (세로)

```
┌──────────────────────┐
│ 레이더(상단 중앙)       │  ← 화면 밖 악귀 방위 점
│ 체력   방 3/5   점수    │
│                      │
│  ░░░░[카메라 영상]░░░░  │  ← 가장자리 어두운 비네트
│  ░░░      ╋      ░░░  │  ← 조준점, 등롱 중심
│  ◁                 ▷  │  ← 화면 밖 악귀 화살표
│                      │
│ 부적 1개        발사(큼) │  ← 왼손 / 오른손 엄지
```

- 결과, 도감, 설정 화면은 Paperoid 공통 가독성 규칙(`docs/game-ui-readability.md`)을 따른다.
- 런 화면 글자는 외곽선 + 반투명 바탕으로 야외 직사광 아래에서도 읽히게 한다.

## 13. 개발 단계

| 단계 | 범위 | 완료 기준 |
| --- | --- | --- |
| 0. 재미 검증 | 방 1개. 등롱 조준, 소리 기반 후방 조우(급습형 1종), 숙이기, 정화. 메뉴·점수·저장 없음 | 안드로이드·iOS 실기기에서 10번 연속 플레이한 뒤 "한 번 더"가 나오는지. 30초 드리프트 5도 이하. 숙이기 오인식 10% 이하 |
| 1. 런 완성 | 방 4개 + 보스, 행동 유형 5종, 도감 8종, 부적 선택, 결과 화면, 일시정지 복귀 | 한 런 2~3분. 혼자 10런 연속 플레이 가능 |
| 2. 오늘의 순찰 | 시드 발급, 결과 제출, 점수판, 도감 숙련·부적 해금 | 두 기기가 같은 날 같은 악귀 순서를 받고 점수판에 반영 |
| 3. 공개 | 접근성 모드, 권한 거부 대응, 회귀 테스트, 게임 목표 안내 등록 | 해루질럿과 같은 수준의 테스트 통과 후 Paperoid 메인·게임 목록·빠른 시작 등록 |

**0단계가 전부다.** 0단계에서 "한 번 더"가 안 나오면 1단계 이후를 만들지 않고 이 문서를 보관한다. 0단계 전에는 다른 단계 코드를 쓰지 않는다.

## 14. 검증 지표

- 0단계: 개발자 본인과 지인 3명 이상이 각 10런 뒤 자발적으로 더 하는지(정성 지표가 유일한 기준)
- 런 시작 후 첫 악귀 소리까지 3초 이내
- 런당 평균 회전 각도 360도 이상(실제로 돌고 있는지)
- 런 중단율(이탈·오류·일시정지 미복귀) 10% 이하
- 10런(약 25분) 배터리 소모 12% 이하

## 15. 변경 원칙

- 런 규칙, 악귀 등급·행동 유형, 안전 규칙, 저장 형태, 오늘의 순찰 규칙을 바꾸면 이 문서와 구현, 목표 안내 문구(`app/game-objectives.js`), 테스트를 같은 커밋에서 고친다.
- 밸런스 수치는 엔진에 한 번만 정의하고 이 문서에는 의미와 원본 위치만 쓴다.
- 용어는 2절 표를 따른다.
- 부록 A의 확장 후보를 본문으로 올릴 때는 0~3단계 완료가 전제다.

## 16. 미결 사항

- 게임명 `야경단`의 상표·도메인 확인
- 숙이기 판정을 가속도 패턴만으로 안정적으로 잡을 수 있는지(0단계에서 확인)
- iOS에서 `DeviceMotion` 권한 거부율이 높을 경우 흔들기·숙이기를 버튼으로 대체할지
- 공포 연출 수위와 어린이 접근성의 경계
- 카메라 없는 모드(권한 거부)의 배경 연출 수준

| 후보 | 내용 | 전제 조건 | 비용 성격 |

위치기반과 분대는 함께 운영 부담을 만든다. 둘 중 하나만 하려면 분대(실내 협동)가 위치기반보다 싸고 안전하다.

## 부록 B. 선행 사례와 종료 원인

| 게임 | 기간 | 결과 | 교훈 |
| --- | --- | --- | --- |
| Ghostbusters World | 2018~2020 | 종료 | IP가 있어도 AR 조우가 1회성 볼거리에 그치면 2년을 못 넘긴다 |
| Harry Potter: Wizards Unite | 2019~2022 | 종료 | 서사 중심 구조는 걷기 게임의 짧고 끊어지는 리듬과 맞지 않았다. 포켓몬 GO와 매출 비교로 정리됐다 |
| Minecraft Earth | 2019~2021 | 종료 | 이동과 모임이 필수인 설계는 외부 변수(팬데믹)에 무너진다 |
| Reality Clash 등 AR 대인 슈팅 | 2016~2018 | 사실상 중단 | 대인 매치는 물리적 밀도가 필요하고, 길에서 사람을 쏘는 연출은 부담이 크다 |
| Devil's Purge | 2024~ | 운영 중(iOS 유료) | 제자리 AR 슈터는 "몸으로 피하고 조준한다"로 재미를 증명했다. 유지율은 아직 미증명 |
| 포켓몬 GO | 2016~ | 운영 중 | 대다수가 AR 모드를 끈다. 살아남은 이유는 AR이 아니라 IP와 수집 |

이 기획이 위치기반을 빼고 **AR을 끌 수 없는 제자리 런**으로 시작하는 이유가 이 표다. 다음 질문 하나만 남는다. "몸을 돌려 조준하는 1~2분이 열 번째에도 즐거운가."
