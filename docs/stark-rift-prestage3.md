# 단계 3 연결 전 보완

구현일: 2026-11-02. 엔진 `0.5.0-prestage3`, 데이터 스키마·저장 형식 4, 통신 규약 5.

## 해결한 연결 문제

1. **실패한 틱 격리**: 틱 시작 상태를 복사하고 규칙 예외 또는 종료 상태 검증 실패 시 복구한 뒤 일시정지한다. 실패한 틱의 명령·난수·엔티티 변경은 남기지 않는다. `SimulationFault`를 반환하며 Worker는 오류를 잠근다. 정상 체크포인트를 불러오기 전까지 재개·새 저장을 거부한다.
2. **부대·이동 저장 계약**: 플레이어별 슬롯 5개와 슬롯당 같은 정의 ID의 소유 유닛 최대 10기, 대열·태세·자동 기술 ID를 저장한다. 엔티티별 명령, 목적지/대상, 경로·커서, 경로 대기 상태, 축별 이동 나머지, 장애물 버전을 저장한다. 삭제 시 슬롯·이동 대상 참조를 정리한다. 실제 슬롯 편집·이동 규칙은 단계 3 작업이다.
3. **Worker 실행**: 실제 `simulation.worker.ts`를 모듈 Worker로 실행한다. `SimulationRuntime`이 초기화·명령 접수·고정 틱·일시정지·저장·불러오기·종료를 담당한다. 메인 스레드가 다른 플레이어 또는 AI를 사칭하는 명령을 보내면 거부한다. 미구현 명령·리플레이 탐색을 성공으로 처리하지 않는다.
4. **스냅샷 흐름 제어**: 가시 정보 마스크를 Transferable로 보내며 미반환 스냅샷은 최대 2개다. 포화 중에는 시뮬레이션을 계속하고 반환 시 최신 틱을 보낸다. 같은 틱의 버퍼 반환으로 새 스냅샷이 무한 생성되지 않는다. 현재는 전송 횟수 제한이며 반환된 메모리의 재사용 풀은 후속 최적화다.
5. **메인 스레드 클라이언트와 내부 호스트**: 클라이언트가 메시지를 검증하고 스냅샷 소비 후 버퍼 ID를 반환한다. `SimulationSession`은 Worker와 `BattleScreen`을 연결한다. 백그라운드 전환 시 정지·저장 요청, 10초마다 검증된 체크포인트 보관, 명시적인 복구·재개, 화면 컨텍스트 손실 후 복구 흐름을 연결한다. 카메라는 실제 세션 값으로 저장하고 복구 시 표시 틱을 초기화한다.
6. **입력 중재**: 단일 `GestureMachine`이 탭, 300ms 그룹 미리보기, 명령 스와이프, 빈 지형 카메라 드래그, 핀치를 구분한다. 전투 유닛 스와이프는 공격이동, 일꾼은 이동으로 전달한다. 핀치 중 선택은 취소하고 취소·포인터 캡처 해제·세 번째 손가락을 처리한다. 실제 히트 테스트·그룹 선택·명령 접수는 주입 인터페이스로 단계 3에서 연결한다.
7. **지도 데이터 연결**: 데이터 번들은 기존 메타데이터와 검증된 전체 전술 지도 모두 수용한다. 등록된 `rift-basin`의 정규화된 지형·자원 전체로 지도 버전을 계산한다. Worker는 등록된 ID·버전만 실행하며 복원 시 지도 밖 엔티티·경로를 거부한다. 지도 버전은 원작 유닛 수치 번들이 완성됐다는 의미가 아니다.

## 검증

- 기존 10,000틱 결정성·저장 복원 검사 유지.
- 명령 예외, 시스템 예외, 잘못된 상태 생성 각각에서 틱 롤백과 정지 확인.
- 부대·경로·이동 나머지 왕복, 잘못된 소유권/중복 부대/경로 커서/나머지 거부 확인.
- 입력 중재와 핀치 취소, 버퍼 포화·반환·동일 틱 무한 재전송 방지 확인.
- 실제 빌드한 브라우저 Worker 엔트리를 Node의 별도 스레드와 메시지/Transferable 채널로 실행해 초기화부터 저장·복구·종료까지 검사.
- 내부 React 세션을 Vite로 별도 번들링해 Worker 자산과 Pixi 동적 import 생성 확인.
- `npm test`로 전체 빌드, 기존 게임/한국어 조사 회귀, 타입 검사와 전용 테스트 실행.

## 남은 범위

- 이 변경은 단계 3의 유닛 선택·경로 탐색·충돌·대열을 구현하지 않는다. 지상/공중·일꾼/전투/건물별 실제 히트 영역은 콘텐츠 정의와 함께 연결해야 한다.
- 내부 호스트는 빈 경기 상태를 실행한다. 본부·일꾼·자원 채취·AI 또는 시야 규칙을 임의로 만들지 않는다. 기본 시야 마스크는 미탐사이며 실제 공급자는 시야 시스템이 연결될 때 제공한다.
- 체크포인트는 현재 세션 메모리에 보관하며 `onSave`로 외부 저장소에 전달한다. IndexedDB 영속 보관·앱 종료 후 복원·자동 명령 재실행·Worker 무응답 감시/자동 재시작은 후속 저장·복구 작업이다.
- 틱 단위 전체 복사·검증은 정확성을 우선한 초기 구현이다. 실제 부대·경로 규모에서 틱 예산을 측정하고 변경 기록/저장소 단위 복구로 최적화할 수 있다. 현재 작은 테스트의 속도를 실제 모바일 성능 보증으로 삼지 않는다.
- 실제 브라우저 GPU·모바일 터치·컨텍스트 손실 검증은 미완료다. 별도 스레드 검사는 브라우저 장치 검증을 대체하지 않는다.
- 공개 `page.tsx`와 Paperoid 게임 목록은 추가하지 않았다. 단계 2 기기 심사는 계속 대기이며, 단계 3의 순수 알고리즘·저장 계약 구현은 이 기반 위에서 진행할 수 있다.
