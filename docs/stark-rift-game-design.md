# Stark Rift 게임 기획서

> 상태: 신규 기획 확정 사항 기록  
> 최종 갱신: 2026-11-01
> 저장소: `itnad/games`

## 1. 프로젝트 원칙

- 최종 게임명은 영문 `Stark Rift`, 한글 표기는 `스타크 리프트`다.
- `Stark Raft`는 사용하지 않는다.
- 게임은 `itnad/games` 저장소의 기존 Paperoid 프로젝트 안에서 개발한다.
- 이전 Claude 초안과 그 초안을 기반으로 만든 Stark Rift 구현은 사용하지 않는다.
- 기존 Stark Rift 소스, 테스트, 설계 문서는 삭제된 상태이며 신규 기획을 기준으로 다시 만든다.
- 현재 단계에서는 게임 코드를 만들지 않고 규칙과 조작 체계를 먼저 확정한다.
- 별도의 `v2` 프로젝트나 시제품 이름을 만들지 않고 같은 Stark Rift를 처음부터 새로 구현한다.
- 게임 월드는 구역·노드 선택 방식이 아닌 자유 이동 RTS 방식이다.
- 게임의 기준 콘텐츠는 스타크래프트 1 브루드워의 테란, 저그, 프로토스 유닛과 건물이다.
- 미세조작을 줄이고 자원 채취, 생산, 건설, 정찰, 이동, 전투, 대열과 전략 선택에 집중한다.
- 모바일 세로 화면만 지원한다. 가로 화면에서는 플레이를 막고 세로 전환 안내를 표시한다.

### 1.2 Paperoid 연결과 공개 순서

- 최종 공개 경로는 `/stark-rift`다.
- 단계별 내부 구현을 별도의 `stark-rift-v2` 경로나 게임으로 등록하지 않는다.
- 완성 기준을 통과하기 전에는 Paperoid 메인, 전체 게임 목록과 빠른 시작에 노출하지 않는다.
- 공개 후 빠른 시작 6개 순서는 `해루질럿`, `스타크 리프트`, `잉카의 다이아몬드`, `오목`, `러브레터`, `큐윅스`다.
- `빠른 시작`은 `이어서 하기` 항목이 있어도 함께 표시한다.
- 공개 시 전체 게임 목록과 게임 목표 안내에도 Stark Rift를 정식 항목으로 등록한다.

## 2. 경기 기본 규칙

- 기본 대전은 플레이어 대 AI의 1대1 섬멸전이다.
- 목표 경기 시간은 8~12분이다.
- 기본 지도 크기는 96×96타일이다.
- 2대2 또는 4인전 지도는 128×128타일을 사용한다.
- 최대 인구수는 100이다.
- 유닛의 비용, 체력, 보호막, 공격력, 방어력, 사거리, 인구수 비용, 기술 에너지 비용과 업그레이드 효과는 브루드워 수치를 기준으로 한다.
- 자원 채취, 건설, 생산, 연구와 저그 변태 시간은 원작의 50%로 단축한다.
- 이동속도와 무기 공격주기는 원작 기준을 유지한다.

### 2.1 시작 상태

- 본부 건물 1개
- 일꾼 4기
- 미네랄 50
- 종족별 원작 시작 인구수

### 2.2 승패 조건

커맨드 센터, 해처리·레어·하이브, 넥서스의 공통 명칭은 **본부 건물**이다.

- 상대의 모든 본부 건물을 파괴하면 즉시 승리한다.
- 자신의 모든 본부 건물을 잃으면 패배한다.
- 건설 중인 본부 건물도 생존 거점으로 인정한다.
- 다른 유닛과 일반 건물이 남아 있어도 본부 건물이 없으면 패배한다.
- 양쪽의 마지막 본부 건물이 같은 순간 파괴되면 무승부다.
- 마지막 본부 건물의 위치를 자동으로 공개하지 않는다.
- 언제든 항복할 수 있다.
- AI 대전은 일시정지할 수 있다.
- 앱이 백그라운드로 전환되면 자동으로 일시정지하고 저장한다.
- 다시 접속하면 진행 중인 경기를 이어서 시작한다.

## 3. 세로 화면 구성

화면을 세로 방향으로 1:2:1 비율로 나눈다. 가로 전용 레이아웃과 가로 플레이는 지원하지 않는다.

플레이 중 가로로 돌리면 즉시 일시정지하고 입력을 막는다. 세로로 돌아오면 카메라·선택·부대 슬롯을 유지하며, 사용자가 `이어서 진행`을 선택해야 재개한다. 가로 상태로 처음 열어도 같은 안내를 표시한다.

- 상단 25%: 미니맵, 자원, 인구수, 본부 수, 알림, 확대, 경기 메뉴
- 중앙 50%: 메인 전장
- 하단 25%: 부대 슬롯, 선택 정보, 생산·건설·기술·명령

기기별 안전 영역과 브라우저 UI를 고려해 25:50:25를 기준으로 조금씩 보정하되, 전장 크기는 메뉴 전환 중 바뀌지 않게 한다.

### 3.1 카메라 확대

- 근접: 약 14×16타일
- 기본: 약 18×20타일
- 광역: 약 24×27타일
- 핀치 중에는 부드럽게 변하고 손을 떼면 가까운 단계에 맞춘다.
- 확대 수준은 실제 시야와 공격 사거리에 영향을 주지 않는다.
- 광역 화면에서는 유닛을 단순 아이콘으로 바꾸어 가독성과 성능을 유지한다.
- 빈 지형에서 시작한 드래그는 카메라 이동이다.
- 화면 가장자리 자동 스크롤은 기본적으로 끄고 설정에서 활성화할 수 있다.

### 3.2 모바일 렌더링 기준

- 유닛을 개별 HTML 요소로 만들지 않고 Canvas 또는 WebGL에서 일괄 렌더링한다.
- 화면 밖 유닛, 건물과 효과는 그리지 않는다.
- 유닛 스프라이트는 아틀라스로 묶어 드로 콜을 줄인다.
- 광역 확대에서는 애니메이션과 세부 효과를 줄이고 단순 아이콘을 사용한다.
- 전장의 안개는 낮은 해상도의 텍스처로 캐시해 갱신한다.
- 핀치 입력과 카메라 변환은 화면 주사율당 한 번만 반영한다.
- 전투 시뮬레이션, 경로 탐색과 AI 판단은 카메라 확대 수준에 영향을 받지 않는다.
- 중급 모바일 기기에서 60fps를 목표로 하고 대규모 전투에서는 30fps까지 안정적으로 낮출 수 있다.

## 4. 미니맵과 상단 정보 패널

상단 너비의 약 55%를 정사각형 미니맵에 사용하고 나머지 영역에 정보를 배치한다.

### 4.1 미니맵 표시

- 아군 유닛: 종족색 점
- 아군 건물: 유닛보다 큰 사각형
- 본부 건물: 테두리가 있는 큰 아이콘
- 현재 발견된 적: 빨간색
- 마지막으로 확인한 적: 30초 동안 흐려지는 반투명 표시
- 정찰하지 않은 지역: 검은색
- 정찰했지만 현재 시야가 없는 지역: 어두운 지형색
- 현재 메인 화면 영역: 흰색 사각 테두리
- 선택한 부대: 밝은 테두리
- 집결지와 순찰 지점: 명령 아이콘

### 4.2 미니맵 조작

- 기본 터치: 카메라 즉시 이동
- 기본 드래그: 카메라 연속 이동
- 생산 건물 선택 후 터치: 집결지 설정
- 순찰 명령 중 터치: 순찰 지점 설정
- 수송선 하차 명령 중 터치: 이동 후 하차 지점 설정
- 일반 유닛 선택 상태에서 터치: 카메라 이동
- 공격 기술은 미니맵에서 사용하지 않는다.
- 명령 모드에서는 미니맵 테두리와 커서를 명령 색상으로 바꾼다.

### 4.3 상단 정보

- 미네랄
- 베스핀 가스
- 현재 인구수/최대 인구수
- 보유 본부 건물 수
- 대기 중인 일꾼 수
- 경기 시간
- 근접·기본·광역 확대 버튼
- 일시정지와 설정 메뉴

인구수는 80%부터 노란색, 90%부터 주황색, 생산이 막히면 빨간색으로 표시한다. 부족한 자원으로 명령을 내리면 해당 자원 수치를 붉게 점멸한다.

### 4.4 알림 우선순위

1. 본부 건물 공격
2. 아군 부대 공격
3. 인구수 부족
4. 건설·생산·연구 완료
5. 일꾼 대기
6. 자원 고갈

- 최근 알림을 최대 3개 표시한다.
- 같은 알림은 묶어서 횟수를 표시한다.
- 알림을 터치하면 발생 위치로 카메라를 이동한다.
- 생산 완료 알림을 터치하면 해당 건물 또는 유닛을 선택한다.
- 알림을 옆으로 밀면 제거한다.
- 은폐된 적에게 공격받으면 위치만 알리고 적의 정체는 표시하지 않는다.
- 본부 공격은 강한 진동, 일반 공격은 짧은 진동을 사용한다.

## 5. 선택과 부대 슬롯

### 5.1 전투 유닛 선택

- 짧은 터치: 해당 유닛 한 기 선택
- 길게 누르기: 주변의 같은 종류 유닛을 가까운 순서로 최대 10기 선택
- 길게 누르는 동안 선택 반경과 포함될 유닛을 미리 표시한다.
- 빈 부대 슬롯이 있으면 선택한 그룹을 자동 등록한다.
- 슬롯이 가득 차면 교체할 슬롯을 선택한다.
- 기존 부대의 유닛을 다른 슬롯에 넣을 때는 이동 내용을 확인한 뒤 재등록한다.
- 화면의 유닛을 직접 짧게 터치하면 기존 부대에 속해 있더라도 해당 유닛 한 기만 선택한다.
- 해당 유닛이 속한 부대 전체를 선택하려면 하단 부대 슬롯을 터치한다.

입력 판정 기준은 다음과 같다.

- 250ms 안에 손을 떼는 것을 개별 선택의 응답 목표로 삼고, 움직임 없이 300ms 전에 손을 떼면 개별 선택으로 판정한다.
- 손가락이 이동하기 시작하면 대기하지 않고 이동 또는 공격이동 스와이프로 판정한다.
- 약 300ms 동안 움직임 없이 누르면 그룹 선택 미리보기를 표시한다.
- 길게 누르는 동안 반경과 포함될 유닛을 강조하고 손을 떼면 그룹을 확정한다.

### 5.2 부대 슬롯

- 전투 부대 슬롯은 5개다.
- 슬롯 하나에는 같은 종류의 전투 유닛을 최대 10기 등록한다.
- 슬롯 터치: 해당 부대 선택
- 슬롯 두 번 터치: 선택 후 해당 부대 중앙으로 카메라 이동
- 슬롯을 가로로 훑기: 지나간 부대들을 복수 선택
- 슬롯에서 중앙 전장으로 위쪽 스와이프: 공격이동
- 일부 유닛이 파괴돼도 슬롯을 유지한다.
- 부대가 전멸하면 슬롯을 자동으로 비운다.
- 기존 슬롯을 선택한 뒤 같은 종류의 유닛을 길게 누르면 최대 10기까지 보충할 수 있다.
- 복수 부대 선택은 일시적인 연합 지휘이며 원래 슬롯 구성은 합쳐지거나 사라지지 않는다.
- 연합 선택을 해제하면 각 부대는 원래 슬롯과 태세를 그대로 유지한다.

### 5.3 일꾼 선택

- 짧은 터치: 일꾼 한 기 선택
- 길게 누르기: 주변 일꾼 최대 10기를 임시 작업반으로 선택
- 일꾼 작업반은 전투 부대 슬롯을 사용하지 않는다.

## 6. 이동과 공격 명령

- 선택 후 지형 터치: 이동만 수행
- 선택 후 적 유닛 또는 적 건물 터치: 집중공격
- 선택된 전투 유닛 또는 전투 부대 슬롯에서 목표 지점까지 스와이프: 공격이동
- 일꾼 또는 일꾼 작업반에서 목표 지점까지 스와이프: 이동만 수행
- 아군 유닛 터치: 해당 아군을 새로 선택
- 이동 전용 명령에서는 적을 만나도 목적지까지 이동한다.
- 목적지 도착 후 일반 경계 상태로 전환한다.
- 수송선은 기본적으로 이동 전용이며 자동으로 적을 피하지 않는다.

명령 우선순위는 다음과 같다.

1. 적 직접 지정 집중공격
2. 이동 전용 명령
3. 공격이동과 전투 태세

## 7. 대열과 전투 태세

### 7.1 대열

- 전열: 병력을 옆으로 넓게 배치하는 기본 전투 대열
- 종대: 좁은 길과 장거리 이동
- 분산: 광역 공격 피해를 줄이도록 간격 확대

좁은 통로에서는 임시로 종대로 압축하고 통과 후 선택한 대열로 복귀한다. 느린 부대에 전체 이동속도를 강제로 맞추지 않고 목적지에서 대열을 완성한다.

### 7.2 전투 태세

- 자율 교전: 가까운 적과 위협도가 높은 적을 공격하고 짧게 추격
- 대열 유지: 추격을 줄이고 대열과 지원 유닛을 보호
- 목표 돌파: 목적지를 우선하며 경로를 막거나 사거리 안에 있는 적만 공격

## 8. 자동 표적 선택

표적 우선순위는 다음과 같다.

1. 플레이어가 직접 지정한 목표
2. 현재 아군을 공격하는 적
3. 아군 지원·공성 유닛을 위협하는 적
4. 사거리 안의 전투 유닛
5. 가까운 일꾼
6. 방어 건물과 생산 건물
7. 본부 건물과 일반 건물

- 공격할 수 없는 공중·지상 목표는 제외한다.
- 탐지되지 않은 은폐 유닛은 선택하지 않는다.
- 같은 부대 안에서 필요한 예상 피해량만 배분해 과도한 집중을 줄인다.
- 직접 지정한 목표에는 선택된 병력이 집중공격한다.
- 근접 유닛은 적 주위로 퍼져 포위한다.
- 원거리 유닛은 최대 사거리를 유지한다.
- 지원 유닛은 아군 최전선 뒤에 머문다.
- 복수 부대가 같은 목적지로 이동하면 부대별 도착 위치를 나눠 겹침을 줄인다.
- 목표를 너무 자주 바꾸지 않도록 짧은 목표 유지 시간을 둔다.

## 9. 자원과 일꾼

- 미네랄, 베스핀 가스, 인구수 체계를 유지한다.
- 본진과 확장기지는 모두 자원 반납 거점이다.
- 가스 건물을 건설해야 가스를 채취할 수 있다.
- 자원은 고갈되며 고갈된 가스에서 원작처럼 소량을 채취할 수 있다.
- 미네랄 한 덩이당 일꾼 2기를 적정 포화로 표시한다.
- 세 번째 일꾼부터 효율이 낮아진다.
- 가스는 일꾼 3기를 적정 포화로 표시한다.
- 자원 UI에 현재 일꾼 수와 권장 수를 표시한다.

### 9.1 일꾼 자동 행동

- 목적지에 도착해 할 일이 없으면 기본적으로 정지한다.
- 자신의 시야 안에 아군 본진 또는 확장기지와 자원이 함께 있을 때만 자동 채취한다.
- 가까운 자원 중 일꾼이 덜 배치된 곳을 우선한다.
- 적 지역이나 정찰 경계에서는 자원을 찾기 위해 돌아다니지 않는다.
- 명시적인 이동, 건설, 정찰 명령은 자동 채취보다 우선한다.
- 공격받으면 알림만 보내고 자동 후퇴하지 않는다.
- 새로 생산된 일꾼도 주변 기지와 자원이 보일 때만 자동 채취한다.
- 자원이 고갈되면 같은 지역에서 다른 자원과 반납 거점을 확인할 수 있을 때만 재배치한다.

## 10. 건설

- 일꾼 선택 후 하단의 건설 버튼으로 건물을 선택한다.
- 메인 화면에서 배치 지점을 터치하면 반투명 미리보기를 표시한다.
- 건설 가능 위치는 초록색, 불가능한 위치는 빨간색이다.
- 자원 채취 동선을 방해하는 위치는 노란색으로 경고한다.
- 다시 터치하거나 확인 버튼을 누르면 건설을 시작한다.
- 가스 건물은 간헐천을 직접 터치한다.
- 미니맵에서는 건설하지 않는다.
- 건물 배치는 숨겨진 격자를 사용하지만 유닛 이동은 자유 이동이다.

종족별 원작 규칙을 유지한다.

- 테란: SCV가 건설을 지속하고 애드온 공간을 확보해야 한다.
- 저그: 드론이 건물로 변태하고 크립 제약을 받는다.
- 프로토스: 프로브가 워프를 시작하고 파일런 동력 제약을 받는다.

건물 버튼을 길게 누르면 연속 건설 모드를 켠다. 여러 일꾼이 선택돼 있으면 배치 위치에서 가까운 명령 가능한 일꾼부터 배정한다.

## 11. 생산과 연구

### 11.1 생산 건물 선택

- 짧은 터치: 생산 건물 하나 선택
- 길게 누르기: 주변의 같은 종류 생산 건물 선택
- 건물 그룹은 부대 슬롯을 사용하지 않는 임시 선택이다.

### 11.2 생산

- 유닛 버튼 터치: 대기열에 한 기 추가
- 여러 건물을 선택하면 대기열이 짧은 건물부터 분배
- 건물별 생산 대기열 최대 5개
- 유닛 버튼 길게 누르기: 반복 생산 켜기·끄기
- 자원 또는 인구수가 부족하면 대기하고 조건이 충족되면 재개
- 진행 중인 생산은 원형 게이지로 표시
- 대기열 항목은 두 번 터치해 취소
- 환불 비율은 원작 규칙을 따른다.

### 11.3 집결지

- 생산 건물을 선택한 뒤 메인 화면 또는 미니맵을 터치해 집결지를 설정한다.
- 전투 유닛은 집결지까지 공격이동한다.
- 일꾼은 집결지까지 이동만 수행한다.

### 11.4 연구와 업그레이드

- 능력 연구와 수치 업그레이드를 탭으로 구분한다.
- 버튼에 현재 단계, 최대 단계, 비용, 남은 시간, 선행 건물과 적용 유닛을 표시한다.
- 같은 연구는 중복 시작할 수 없다.
- 여러 연구 건물을 선택하면 비어 있는 건물에 자동 배정한다.
- 연구 취소는 두 번 터치로 확인한다.

## 12. 수송

### 12.1 탑승

1. 드롭십, 셔틀 또는 수송 가능한 오버로드 선택
2. 탑승 버튼 터치
3. 메인 화면의 아군 유닛 또는 하단 부대 슬롯 터치
4. 대상 유닛이 수송선까지 이동해 탑승

- 여러 수송선을 선택하면 원작의 수용 공간에 맞춰 자동 분배한다.
- 공간이 부족하면 가까운 유닛부터 탑승한다.
- 수송 중에도 기존 부대 슬롯을 유지한다.
- 오버로드는 원작의 수송 업그레이드 후 사용할 수 있다.
- 여러 수송선을 함께 선택하면 탑승 유닛 목록을 수송선별로 구분해 표시한다.
- 부대 슬롯에서 수송 중인 부대를 선택하면 해당 부대를 태운 수송선을 강조한다.

### 12.2 하차

- 하차 버튼을 누르고 메인 화면 또는 미니맵에서 지점을 지정한다.
- 현재 위치를 지정하면 즉시 하차한다.
- 메인 화면에서는 지정한 대열에 맞춰 배치한다.
- 미니맵에서는 해당 지역의 가장 가까운 유효 지형에 하차한다.
- 여러 수송선은 서로 겹치지 않도록 위치를 나눈다.
- 하차한 유닛은 기존 부대 슬롯과 전투 태세를 유지한다.
- 수송선이 파괴되면 탑승 병력도 소멸한다.
- 하차 후 별도 명령이 없으면 해당 위치에서 경계한다.

### 12.3 개별 하차

- 수송선을 선택하면 탑승 유닛을 개별 초상화로 표시한다.
- 초상화에는 유닛 종류, 체력, 보호막과 에너지를 표시한다.
- 초상화를 한 번 터치하면 해당 유닛만 현재 위치에 즉시 하차한다.
- 여러 초상화를 차례로 터치해 원하는 유닛만 순서대로 내릴 수 있다.
- 전체 하차 버튼을 별도로 둔다.
- 초상화를 길게 누르면 하차시키지 않고 상세 정보를 보여준다.

## 13. 기본 기술 규칙

### 13.1 스팀팩

- 마린·파이어뱃이 실제 교전을 시작할 때 주변에 치료 가능한 메딕이 있으면 자동 사용한다.
- 메딕의 에너지가 부족하거나 유닛 체력이 너무 낮으면 자동 사용하지 않는다.
- 효과가 끝나기 전에는 중복 사용하지 않는다.
- 메딕이 없을 때는 사용자가 기술 버튼으로 수동 사용한다.

### 13.2 시즈 모드

- 사용자가 기술 버튼으로 직접 토글한다.
- 여러 탱크를 선택하면 동시에 전환한다.
- 시즈 상태에서 이동 명령을 받아도 자동으로 해제하지 않는다.

### 13.3 사이오닉 스톰

- 하이 템플러가 여러 적에게 공격받으면 사거리 안에서 적이 가장 밀집한 영역에 자동 시전한다.
- 한 명의 적에게만 공격받으면 스톰을 쓰지 않고 가까운 교전 중인 아군 뒤로 후퇴한다.
- 자신이 공격받지 않는 교전에서는 가장 밀집한 적을 향해 이동하되 아군 최전선보다 앞으로 나가지 않는다.
- 전방 아군이 없으면 적에게 접근하지 않는다.
- 아군 피해와 기존 스톰 영역을 고려해 중복을 방지한다.
- 여러 하이 템플러는 서로 다른 지역을 맡는다.
- 사용자가 직접 지정하면 수동 명령을 우선한다.
- 자동 스톰은 기본 활성화하며 기술 버튼을 길게 눌러 끌 수 있다.

### 13.4 상태 변화 기술

클로킹, 버로우와 시즈 모드처럼 자신의 상태를 바꾸는 기술은 수동 토글이다.

- 고스트·레이스 클로킹: 수동 토글
- 저그 버로우: 수동 토글
- 러커: 직접 버로우해야 공격 가능
- 이동·공격 명령으로 자동 해제하지 않음
- 고스트·레이스는 에너지가 소진되면 클로킹이 해제됨
- 버로우 상태의 유닛은 직접 해제하기 전까지 이동하지 않음
- 다크 템플러·옵저버 영구 은폐와 아비터 은폐장은 원작 고유 효과 유지

## 14. 대상 지정 기술과 자동 시전

### 14.1 공통 조작

- 기술 버튼 짧게 터치: 한 번 수동 사용
- 기술 버튼 길게 누르기: 조건부 자동 시전 켜기·끄기
- 자동 상태는 기술 버튼에 `A`로 표시한다.
- 부대를 선택하고 토글하면 같은 시전자 전체에 적용한다.
- 새로 부대에 들어온 같은 종류 유닛은 부대의 설정을 이어받는다.
- 저장 후 이어서 할 때 자동 시전 설정도 유지한다.
- 수동 지정은 자동 판단보다 우선한다.
- 여러 시전자가 같은 대상 또는 영역에 기술을 중복 사용하지 않는다.
- 자동 시전을 위해 아군 최전선보다 앞으로 나가지 않는다.
- 여러 시전자를 선택하고 수동 기술을 지정하면 사거리와 에너지가 적합한 한 기만 먼저 시전한다.
- 자동 시전은 현재 시야에서 확인한 유효 대상만 평가한다.
- 위치 사수 상태에서는 자동 시전을 위해 현재 위치를 벗어나지 않는다.
- 범위 기술은 예상 범위와 아군 피해 위험을 시전 전에 표시한다.

### 14.2 기본 자동 기술

- 메딕 힐
- 메딕 리스토레이션
- 사이언스 베슬 디펜시브 매트릭스
- 하이 템플러 사이오닉 스톰
- 리버 스캐럽 자동 보충
- 캐리어 인터셉터 자동 보충

### 14.3 선택 가능한 자동 시전

- 메딕: 옵티컬 플레어
- 고스트: 락다운
- 사이언스 베슬: EMP, 이레디에이트
- 배틀크루저: 야마토 포
- 퀸: 패러사이트, 인스네어, 스폰 브루들링
- 디파일러: 다크 스웜, 플레이그
- 다크 아콘: 피드백, 마엘스트롬, 마인드 컨트롤

### 14.4 계속 수동으로 유지할 기술

- 고스트 핵 공격
- 아비터 리콜
- 디파일러 컨슘
- 아콘·다크 아콘 합체
- 퀸의 커맨드 센터 감염
- 벌처 스파이더 마인 배치
- 클로킹, 버로우, 시즈 모드

SCV 수리는 미네랄을 소모하므로 수리 대상을 사용자가 직접 지정한다. 여러 SCV를 선택해 수리하면 실제로 필요한 수만 참여한다.

실드 배터리는 범위 안에서 보호막이 손상된 아군이 정지하면 자동으로 충전한다. 전투 또는 이동 중인 유닛을 강제로 불러오지 않으며, 사용자가 대상을 직접 지정하면 해당 유닛을 우선한다.

리버 스캐럽과 캐리어 인터셉터의 자동 보충은 설정한 최소 보유 미네랄 아래로 내려가면 일시 중지한다. 사용자가 내린 생산과 업그레이드 명령이 자동 보충보다 우선한다.

### 14.5 자동 시전 목표 배분

- 메딕은 탐지기와 시야가 넓은 적에게 옵티컬 플레어를 분산한다.
- 고스트는 시즈 탱크, 골리앗, 드라군, 리버, 캐리어 등 고가 기계 유닛에 락다운을 분산한다.
- 범위 기술은 이미 적용된 영역을 피한다.
- 죽을 만큼 피해가 예약된 대상에 고비용 기술을 낭비하지 않는다.
- 에너지가 부족한 시전자는 후방에서 대기한다.
- 디펜시브 매트릭스는 집중공격을 받는 공성 유닛, 수송선과 고가 유닛을 우선한다.
- EMP는 보호막 또는 에너지가 많은 적이 밀집한 영역을 우선한다.
- 이레디에이트는 디파일러 등 중요한 생체 유닛을 우선하되 아군 생체 유닛이 밀집한 곳은 피한다.
- 퀸은 수송선·탐지기에 패러사이트, 빠른 밀집 병력에 인스네어, 고가 지상 유닛에 스폰 브루들링을 우선한다.
- 다크 아콘은 에너지가 많은 시전자에 피드백, 생체 유닛 밀집 지역에 마엘스트롬을 사용한다.
- 마인드 컨트롤은 안전하게 접근할 수 있는 고가 유닛만 평가한다.
- 핵 공격은 자동화하지 않고 조준 표식과 경고를 명확하게 표시한다.

## 15. 시야, 정찰과 탐지

- 한 번도 보지 못한 지역은 검은색이다.
- 정찰했지만 현재 시야가 없는 지역은 어두운 전장의 안개로 표시한다.
- 아군이 이동하거나 파괴되면 해당 지역의 실시간 시야는 즉시 사라진다.
- 적 유닛은 마지막 위치에 흐린 표식으로 남고 30초 동안 점차 사라진다.
- 마지막 위치 표식은 갱신되지 않으며 공격할 수 없다.
- 적 건물은 마지막으로 확인한 모습을 기억하고 다시 정찰했을 때 갱신한다.
- 지형과 자원 위치는 한 번 정찰하면 계속 기억한다.
- 은폐·버로우 유닛은 탐지기가 있는 현재 시야에서만 표시한다.
- 탐지되지 않은 적은 메인 화면과 미니맵에서 선택하거나 공격할 수 없다.

## 16. 지형 규칙

- 지형은 저지대, 고지대, 경사로, 통로와 이동 불가 지역으로 나눈다.
- 지상 유닛은 절벽, 물과 우주 지형을 통과할 수 없고 경사로로만 고지대로 이동한다.
- 공중 유닛은 지형 이동 제약을 무시한다.
- 저지대에서 고지대를 공격하면 약 50% 확률로 빗나간다.
- 아군이 고지대 시야를 확보하면 빗나감 불이익을 제거한다.
- 기술과 범위 효과는 고저 차이로 빗나가지 않는다.
- 고지대에 별도 공격력·방어력 보너스를 주지 않는다.
- 사거리와 시야가 확보되면 절벽 너머를 공격할 수 있다.
- 대형 유닛과 아군·적군 모두 충돌 판정을 적용한다.
- 목적지가 막혀 있으면 가장 가까운 도달 가능 위치까지 이동하고 경고한다.

## 17. 첫 지도: 균열 분지

96×96타일의 180도 회전 대칭형 1대1 지도다.

- 플레이어 A는 북서쪽, 플레이어 B는 남동쪽에서 시작한다.
- 본진은 고지대이며 경사로 하나로 앞마당과 연결한다.
- 중앙은 여러 방향에서 진입할 수 있는 넓은 저지대다.
- 좌우에는 외곽 확장기지를 배치한다.
- 중심을 가로지르는 우주 균열은 지상 이동 불가 지형이다.
- 중앙의 짧은 경로와 좌우의 넓은 우회 경로를 제공한다.
- 첫 지도에는 섬과 파괴 가능한 장애물을 넣지 않는다.
- 중앙 자원 지역은 네 방향이 열려 있어 장기간 방어하기 어렵게 만든다.
- 시즈 탱크나 리버가 중앙 전체를 한 지점에서 통제하지 못하도록 고지대를 분리한다.

### 17.1 자원 배치

각 진영에는 다음 거점을 둔다.

- 본진: 미네랄 8, 가스 1
- 앞마당: 미네랄 7, 가스 1
- 외곽 확장기지: 미네랄 6, 가스 1
- 중앙 경쟁 지역: 미네랄 8, 가스 2

지도는 미네랄 거리, 가스 거리, 건설 공간과 본진 간 이동 거리를 대칭으로 맞춘다. 경기 전에 지도 형태와 자원 위치를 볼 수 있지만 경기 중 적의 현재 상태는 정찰해야 한다.

## 18. 하단 명령창

하단 맨 위에는 부대 슬롯 5개를 고정한다. 아래 영역은 왼쪽 약 28%를 선택 정보에, 오른쪽을 4×2 명령 격자에 사용한다.

### 18.1 선택 정보

- 초상화와 이름
- 체력, 보호막, 에너지
- 선택된 유닛 수
- 현재 대열과 전투 태세
- 클로킹, 버로우, 시즈와 수송 상태
- 자동 시전 중인 기술
- 초상화를 길게 누르면 상세 능력치 표시

### 18.2 기본 명령

- 정지: 현재 이동·공격·순찰 명령 취소 후 일반 경계 상태
- 위치 사수: 이동하지 않고 사거리 안의 적만 공격
- 순찰: 현재 위치와 지정 지점을 반복 이동하고 교전 후 경로 복귀

- 태세: 자율 교전·대열 유지·목표 돌파 선택

자주 쓰는 기술은 최대 3개를 바로 표시한다. 기술이 더 많으면 마지막 칸에 더보기 버튼을 표시한다. 핵 공격과 리콜 같은 위험한 기술은 더보기 화면에 둔다.

모든 터치 버튼은 최소 52dp로 유지한다.

## 19. AI 공통 원칙

- AI도 플레이어와 같은 자원, 생산 시간, 시야와 전장의 안개를 사용한다.
- 정찰하지 않은 병력, 건물과 확장기지를 알 수 없다.
- 숨겨진 생산 대기열과 플레이어 명령을 읽지 않는다.
- 난이도에 따라 유닛 능력치와 비용을 바꾸지 않는다.
- 본부 건물을 맵 구석에 지어 패배만 지연하지 않는다.
- 같은 자동 시전, 중복 방지와 에너지 규칙을 적용한다.
- 이동 유닛의 마지막 위치는 플레이어와 같이 30초까지만 기억한다.
- 적 건물, 지형과 자원은 플레이어와 같이 마지막 확인 상태를 기억하며 다시 정찰했을 때 갱신한다.

### 19.1 난이도

| 난이도 | 전략 재평가 | 전투 반응 | 특징 |
| --- | ---: | ---: | --- |
| 쉬움 | 약 60초 | 약 2초 | 느린 생산·확장, 단방향 공격, 제한된 고급 기술 |
| 보통 | 약 30초 | 약 1초 | 정상 운영, 정찰 기반 조합 변경과 후퇴 |
| 어려움 | 약 15~20초 | 약 0.6초 | 반복 정찰, 견제, 양방향 공격, 수송과 기술 활용 |

기본 난이도는 보통이다.

### 19.2 전략 전환

- 초반 압박, 균형 운영, 기술 발전과 빠른 확장 중 하나를 선택한다.
- 새 전략 평가가 현재 전략보다 충분히 높을 때만 바꾼다.
- 전략 변경 후 최소 45초 동안 급하게 다시 바꾸지 않는다.
- 이미 생산한 병력을 버리지 않고 새 조합의 지원 병력으로 사용한다.
- 비슷한 전략은 저장 가능한 시드를 이용한 가중 무작위로 선택한다.
- 오래된 정찰 정보의 신뢰도를 낮추고 정보가 부족하면 정찰을 우선한다.

### 19.3 공격과 후퇴

- 쉬움은 추정 전력 1.5배 우세 시 주력 공격을 고려한다.
- 보통은 1.15배 우세하거나 조합이 유리할 때 공격한다.
- 어려움은 비슷한 전력이라도 고지대, 포위와 측면 조건이 좋으면 공격한다.
- 주력의 약 40%를 잃거나 핵심 지원 유닛을 모두 잃으면 후퇴를 고려한다.
- 예상하지 못한 적 증원이나 강한 방어가 나타나면 재평가한다.
- 공격을 지나치게 미뤄 경기가 정체되지 않도록 확장 또는 압박을 실행한다.

## 20. 종족별 AI 전략

### 20.1 테란

**마린·메딕 기본 운영**

- 인구수 8 서플라이 디포, 10 배럭, 12 전후 리파이너리
- 배럭 건설 시작 후 SCV 정찰
- 두 번째 배럭과 아카데미, 스팀팩 연구
- 첫 공격 기준: 마린 8, 메딕 2
- 저글링·질럿 비중이 높으면 파이어뱃 2 추가
- 메딕 전멸 또는 전투력 약 40% 이하에서 후퇴
- 러시를 확인했을 때만 벙커 건설

**시즈 탱크 기계화**

- 팩토리, 머신 숍, 시즈 연구, 두 번째 팩토리
- 탱크 3, 벌처 4, 수리용 SCV 2를 기본으로 구성
- 공중 위협이 있으면 골리앗 2~4 추가
- 탱크 일부가 엄호하고 나머지가 전진하는 방식 사용
- 모든 탱크가 동시에 시즈를 해제하지 않음

**레이스와 드롭십**

- 적의 대공과 탐지가 약할 때 레이스 3~5기로 일꾼과 고립 유닛 견제
- 드롭 조합: 마린 6+메딕 2, 마린 4+파이어뱃 2+메딕 2, 탱크 2 또는 벌처 4
- 정찰된 약한 경로만 사용하고 발각된 경로는 변경
- 보통은 단일 견제, 어려움은 정면 공격과 측면 드롭 병행

### 20.2 저그

**저글링·히드라 기본 운영**

- 오버로드, 스포닝 풀, 두 번째 해처리, 익스트랙터, 히드라리스크 덴
- 저글링 이동속도, 히드라 사거리와 이동속도 연구
- 저글링 8~10, 히드라 6~8을 기본으로 구성
- 저글링이 전열과 측면, 히드라는 후열

**러커 매복**

- 레어, 러커 변태 연구, 러커 4~6 생산
- 통로, 확장기지 입구와 전투 부대 후방에서 직접 버로우
- 적의 이동을 전맵 정보로 미리 알지 않고 정찰 경로만 활용

**뮤탈리스크 견제**

- 레어, 스파이어, 뮤탈리스크 6~9
- 일꾼, 고립된 지원·공성 유닛과 수송선을 우선 공격
- 확인된 대공 방어를 피하고 같은 경로를 반복하지 않음
- 완벽한 겹치기 조작을 사용하지 않음

**울트라리스크·디파일러**

- 하이브, 울트라리스크 캐번, 디파일러 마운드
- 울트라 4~6, 저글링 8~10, 디파일러 2, 히드라 4~6
- 다크 스웜으로 진입로를 만들고 플레이그는 밀집한 적에게 사용
- 컨슘은 체력이 낮거나 전투에서 떨어진 저글링을 우선 희생

### 20.3 프로토스

**질럿·드라군 기본 운영**

- 인구수 7 전후 파일런, 9 전후 게이트웨이
- 게이트웨이 시작 후 프로브 정찰
- 어시밀레이터, 사이버네틱스 코어, 두 번째 게이트웨이
- 드라군 사거리 연구
- 질럿 4~6, 드라군 6~8을 기본으로 구성

**하이 템플러·리버 지원**

- 밀집 지상군에는 하이 템플러와 사이오닉 스톰
- 방어선과 밀집 지상군에는 로보틱스, 리버 1~2, 셔틀 1
- 리버를 반복해서 완벽하게 태웠다 내리는 초고속 조작은 사용하지 않음
- 어려움 후반에는 두 지원 체계를 함께 사용할 수 있음

**다크 템플러 침투**

- 다크 템플러 2~4기를 정면과 다른 경로로 이동
- 탐지기가 없는 일꾼, 본부와 테크 건물을 우선 공격
- 탐지기가 나타나면 목표를 포기하고 후퇴

**캐리어와 아비터**

- 본부 건물 2개 이상과 안정된 수입이 있을 때 캐리어 평가
- 캐리어 3~5와 인터셉터, 옵저버·드라군·커세어 호위
- 아비터는 강한 지상 주력군의 후방에서 은폐장 제공
- 스테이시스는 적 병력 분리에 사용
- 리콜은 정찰이 끝난 위치에만 사용하며 플레이어 조작은 수동

### 20.4 고급 전략의 난이도 제한

- 쉬움 테란은 레이스 견제와 드롭 작전을 사용하지 않는다.
- 보통 테란은 레이스 견제 또는 드롭 작전 하나만 수행한다.
- 어려움 테란은 지상 주력군 공격과 측면 드롭을 함께 수행할 수 있다.
- 쉬움 저그는 러커를 방어 위치에서만 사용하고 뮤탈리스크 견제와 디파일러를 사용하지 않는다.
- 보통 저그는 러커를 통로·주력 후방에서 사용하고 뮤탈리스크 한 부대로 한 지역씩 견제한다.
- 어려움 저그는 정면 병력과 측면 러커 매복, 지상 공격과 뮤탈리스크 견제를 병행할 수 있다.
- 쉬움 프로토스는 하이 템플러 또는 리버 중 하나를 단순하게 사용하고 다크 템플러 침투를 사용하지 않는다.
- 보통 프로토스는 정찰 결과에 따라 지원 유닛을 하나 선택하고 다크 템플러 한 부대로 침투한다.
- 어려움 프로토스는 하이 템플러와 리버를 함께 사용하거나 정면 공격과 다크 템플러 침투를 병행할 수 있다.

### 20.5 특수 작전의 공정성

- 레이스, 뮤탈리스크와 캐리어는 확인된 대공 방어를 피하지만 보이지 않는 방어 위치를 미리 알지 못한다.
- 레이스는 체력이 낮아지면 수리 가능한 기지로, 뮤탈리스크는 재생 가능한 안전 지역으로 후퇴한다.
- 수송 작전은 정찰된 경로를 사용하고 방어가 확인된 같은 경로를 반복하지 않는다.
- 드롭 부대가 불리해지면 생존한 수송선으로 회수를 시도한다.
- 러커는 보이지 않는 적의 이동을 예측해 즉시 매복하지 않고 마지막 정찰 경로만 활용한다.
- 다크 템플러는 탐지기가 나타나면 목표를 포기하고 후퇴한다.
- 리버 셔틀과 공중 유닛은 사람이 대응하기 어려운 완벽한 반복 조작을 사용하지 않는다.
- AI의 핵 공격은 어려움에서만 정찰된 밀집 지역 또는 본부 건물을 대상으로 고려하며 동일한 경고를 제공한다.

## 21. 게임 시작과 대전 설정

- 저장된 경기가 있으면 게임 진입 화면에서 `이어하기`를 가장 크게 표시한다.
- 이어하기 아래에 `새 게임`을 표시한다.
- 진행 중인 경기는 한 개만 자동 저장한다.
- 저장된 경기가 있을 때 새 게임을 선택하면 기존 경기 교체 여부를 확인한다.
- 새 게임 설정은 화면을 여러 단계로 나누지 않고 한 화면에서 처리한다.
- 설정 항목은 플레이어 종족, 상대 종족, AI 난이도와 지도다.
- 상대 종족의 기본값은 무작위다.
- AI 난이도의 기본값은 보통이다.
- 지도의 기본값은 균열 분지다.
- 선택이 끝나면 `전투 시작` 버튼으로 경기를 시작한다.
- 종족 카드에는 대표 유닛과 초반·중반·후반 성향을 짧게 표시한다.
- 마지막으로 사용한 설정을 기억해 다음 새 게임에 기본값으로 제시한다.

## 22. 보류한 항목

### 22.1 명령 예약과 다중 경유지

- 모바일 조작이 복잡해질 수 있으므로 초기 구현에서는 제외한다.
- 초기 버전은 직접 이동, 공격이동, 집중공격, 순찰과 수송 하차 명령만 사용한다.
- 건설 반복은 이미 확정한 연속 건설 기능으로 처리한다.
- 실제 조작 테스트에서 필요성이 확인될 때 예약 명령과 다중 경유지를 다시 검토한다.

## 23. 테크트리 표시

- 상단 메뉴의 `테크` 버튼으로 전체 화면 테크트리를 연다.
- AI 대전에서는 테크트리를 보는 동안 자동으로 일시정지한다.
- 기본·중급·고급 테크를 세로 방향으로 배치한다.
- 지상군, 공중군, 지원과 방어 계열은 좌우 가지로 구분한다.
- 건설 완료 항목은 종족색으로, 현재 사용 가능한 항목은 밝은 테두리로 표시한다.
- 연구·생산 중인 항목에는 진행률을 표시한다.
- 선행 조건이 부족한 항목은 어둡게 표시한다.
- 노드를 터치하면 비용, 시간, 기능과 필요한 선행 건물을 표시한다.
- `관련 건물 선택`을 누르면 테크트리를 닫고 해당 생산·연구 건물을 선택한다.
- 건설이 필요한 경우 `건설 일꾼 선택`으로 연결한다.
- 테크트리 화면에서 직접 생산하거나 연구하지 않는다.
- 테크트리를 닫으면 기존 카메라 위치와 부대 선택 상태를 유지한다.
- 경기 밖에서는 세 종족 전체를 볼 수 있는 도감으로 제공한다.
- 경기 중에는 플레이어가 선택한 종족의 테크트리만 표시한다.

## 24. 튜토리얼과 첫 경기 안내

- 처음 실행하면 `조작 연습`을 권장하지만 건너뛸 수 있다.
- 기본 튜토리얼은 약 5분이며 조작을 이해하기 쉬운 테란으로 진행한다.
- 긴 설명문보다 실제 터치 위치와 버튼을 강조해 직접 수행하게 한다.
- 각 단계를 완료하면 다음 단계로 진행한다.
- 유닛을 잃어 진행할 수 없으면 현재 단계만 즉시 재시작한다.
- 설정 메뉴에서 언제든 튜토리얼을 다시 실행할 수 있다.

기본 튜토리얼 순서는 다음과 같다.

1. 메인 화면과 미니맵 이동
2. 확대·축소
3. 유닛 개별 선택과 길게 눌러 부대 등록
4. 이동, 공격이동과 집중공격 구분
5. 일꾼 자원 채취와 서플라이 디포 건설
6. 배럭 생산과 집결지 설정
7. 정찰과 전장의 안개
8. 적 본부 건물 파괴

첫 실제 경기에서는 필요한 순간에만 상황별 도움말을 표시한다.

- 인구수가 차면 보급 건물 안내
- 대기 일꾼이 생기면 알림 설명
- 첫 확장 시 본부 건물과 자원 포화 설명
- 첫 기술 유닛 생산 시 자동 시전 토글 안내
- 같은 도움말은 한 번 본 뒤 반복하지 않는다.
- 모든 도움말은 설정에서 끌 수 있다.

저그와 프로토스에는 별도의 짧은 종족 연습을 제공한다. 저그는 크립과 변태, 프로토스는 파일런 동력과 보호막처럼 공통 튜토리얼과 다른 규칙만 추가로 가르친다.

## 25. 그래픽과 애니메이션

- 3D처럼 보이는 고해상도 2.5D 스프라이트 방식을 사용한다.
- 전장은 약간 위에서 내려다보는 3/4 시점이다.
- 유닛과 건물은 입체감 있는 2D 스프라이트로 표현한다.
- 이동과 공격 방향은 8방향이다.
- 렌더링은 60fps, 유닛 애니메이션은 30fps를 기준으로 보간한다.
- 근접 확대에서는 이동·공격·피격·사망 애니메이션을 표시한다.
- 광역 확대에서는 애니메이션을 줄이고 식별용 아이콘으로 전환한다.
- 지형은 타일 기반으로 만들되 장식 레이어를 사용해 경계와 반복 무늬를 줄인다.

종족별 시각 방향은 다음과 같다.

- 테란: 어두운 강철, 산업 장비와 주황색 조명
- 저그: 짙은 적갈색과 보라색, 살아 움직이는 유기 조직
- 프로토스: 검은 소재와 금색 장식, 청록색 에너지
- 플레이어 색상은 어깨, 외피와 조명 등 제한된 부분에 적용한다.
- 작은 화면에서도 역할이 다른 유닛의 실루엣을 명확히 구분한다.

전투 효과는 정보 전달을 우선한다.

- 공격 사거리와 기술 범위를 얇고 선명하게 표시한다.
- 피격 방향과 상태 이상을 색상과 아이콘으로 표시한다.
- 폭발과 범위 기술이 유닛을 오래 가리지 않도록 효과 지속시간을 제한한다.
- 화면 흔들림은 큰 폭발에서만 약하게 사용하고 설정에서 끌 수 있다.
- 체력바는 선택됐거나 피해를 받은 유닛만 표시한다.
- 선택 링, 부대 번호와 자동 기술 상태를 전투 효과보다 위에 표시한다.
- UI는 짙은 반투명 패널과 선명한 아이콘을 사용한다.
- 그래픽 품질은 낮음·기본·높음 3단계로 제공한다.

## 26. 음악, 효과음과 접근성

### 26.1 음악

- 종족별로 서로 다른 신규 배경음을 사용한다.
- 초반 운영, 교전과 본부 위기의 3단계로 음악 강도가 자연스럽게 변한다.
- 전투가 끝나면 운영 음악으로 서서히 복귀한다.
- 승리·패배 음악은 짧게 재생한다.
- 앱이 백그라운드로 전환되면 음악을 정지한다.

### 26.2 효과음과 음성

- 선택·이동 명령은 짧고 약한 확인음을 사용한다.
- 공격이동·집중공격은 더 강한 확인음을 사용한다.
- 본부 공격, 인구수 부족과 생산 완료는 서로 다른 경고음을 사용한다.
- 여러 유닛을 선택해도 대표 음성 한 번만 재생한다.
- 같은 명령 음성이 연속 반복되지 않도록 간격을 둔다.
- 본부 공격과 중요 연구 완료는 한국어 음성으로 알린다.
- 모든 음성 알림은 화면 자막과 함께 표시한다.
- 보이지 않는 적의 종류를 음성으로 미리 알리지 않는다.
- 대규모 전투에서는 가까운 공격과 중요 경고를 우선하고 동시 효과음 수를 제한한다.

### 26.3 진동

- 일반 선택: 매우 약한 진동
- 명령 완료: 짧은 진동
- 잘못된 위치 또는 자원 부족: 두 번의 짧은 진동
- 일반 공격 경고: 중간 진동
- 본부 건물 공격: 강한 진동
- 진동은 강도를 조절하거나 완전히 끌 수 있다.

### 26.4 접근성

- 전체·음악·효과음·음성 음량을 각각 조절한다.
- 적록·청황 등 색각 보정 모드를 제공한다.
- 색상 외에도 아이콘과 테두리 모양으로 아군·적군을 구분한다.
- UI 글자 크기는 기본·크게를 제공한다.
- 화면 흔들림, 강한 섬광과 불필요한 애니메이션을 각각 줄이거나 끌 수 있다.
- 길게 누르기 시간을 사용자가 조절할 수 있다.
- 자막 항상 표시 옵션을 제공한다.
- 좌우 어느 손으로도 사용할 수 있도록 핵심 버튼 위치 교환 옵션을 제공한다.

## 27. 저장과 리플레이

### 27.1 진행 중 경기 저장

- 진행 중인 경기는 한 개만 저장한다.
- 10초마다 자동 저장한다.
- 앱이 백그라운드로 전환되거나 일시정지할 때 즉시 저장한다.
- 브라우저 IndexedDB에 저장한다.
- 최근 저장본 3개를 순환 보관한다.
- 최신 저장본이 손상되면 직전 정상 저장본으로 복구한다.
- 수동 저장·불러오기는 제공하지 않는다.
- 이어서 시작하면 유닛, 건물, 자원, AI 상태, 자동 기술 설정, 카메라와 부대 슬롯을 복원한다.
- 새 게임을 시작하면 기존 진행 경기를 교체한다.
- 경기가 끝나면 진행 중 저장본을 삭제하고 결과와 리플레이를 보관한다.

### 27.2 리플레이

- 초기 상태, 무작위 시드, 플레이어와 AI의 명령을 기록한다.
- 빠른 탐색을 위해 일정 간격으로 요약 스냅샷을 저장한다.
- 최근 경기 10개를 자동으로 보관한다.
- 사용자가 `보관`으로 지정한 리플레이는 자동 삭제하지 않는다.
- 재생, 일시정지와 0.5배·1배·2배·4배 속도를 제공한다.
- 타임라인에서 원하는 시점으로 이동할 수 있다.
- 플레이어 시야와 전체 지도 시야를 전환할 수 있다.
- 유닛·부대를 터치하면 당시 체력, 명령과 자동 기술 상태를 확인할 수 있다.
- 리플레이에서는 명령을 내리거나 결과를 변경할 수 없다.
- 저장 공간이 부족하면 보관하지 않은 오래된 리플레이부터 삭제한다.
- 게임 엔진 버전을 함께 기록하고 호환되지 않는 기록은 호환 불가로 안내한다.

## 28. 온라인 대전 보류

- 초기 구현은 플레이어 대 AI 오프라인 게임에 집중한다.
- 온라인 1대1은 오프라인 전투, 저장과 AI가 안정된 뒤 다시 검토한다.
- 온라인을 추가할 때는 서버가 초당 여러 번 전투 전체를 계산하는 방식보다 명령 중계식 동기화를 우선 검토한다.
- 양쪽 클라이언트가 같은 규칙 엔진으로 전투를 계산하고 서버는 명령 순서와 연결 상태만 중계한다.
- 서버는 1초마다 양쪽 상태 검증값을 비교하고 약 15초마다 압축 복구 지점을 보관한다.
- 1초 이상 연결이 끊기면 양쪽 경기를 같은 시점에서 일시정지하는 방식을 기준으로 한다.
- 재접속 시 마지막으로 일치한 복구 지점과 이후 명령을 이용해 복원한다.
- 명령 중계 방식은 서버 부하가 낮지만 전장의 안개 조작을 강하게 막기 어렵다는 한계가 있다.
- 온라인을 도입하더라도 먼저 친선·일반 대전을 대상으로 하고 경쟁 순위 대전은 별도로 검토한다.
- 이 절의 온라인 수치는 실제 온라인 개발을 시작할 때 부하와 연결 테스트를 거쳐 다시 확정한다.

## 29. 밸런스 검증 기준

- 평균 경기 시간은 8~12분을 목표로 한다.
- 첫 본격 교전은 경기 시작 후 약 2~3분을 기준으로 한다.
- 정상적인 경기에서 확장기지 1~2개를 사용하도록 유도한다.
- 동일 난이도 AI 대전 기준 각 종족 승률은 45~55%를 목표로 한다.
- 원작의 비용, 체력, 공격력과 상성을 기본값으로 사용한다.
- 문제가 생기면 AI 판단과 지도 구조를 먼저 조정한다.
- 그다음 채취·생산 시간을 조정한다.
- 비용을 조정하고도 해결되지 않을 때만 체력·공격력을 변경한다.
- 한 번에 하나의 수치만 바꾸고 결과를 기록한다.
- 세 종족의 9개 대진을 여러 무작위 시드로 반복 시험한다.
- 모바일에서 전투 중 30fps 아래로 지속해서 떨어지지 않아야 한다.
- 자동 기술이 수동 기술보다 지나치게 완벽하지 않도록 사용률과 효율을 측정한다.

## 30. 게임 내 버그 리포트

### 30.1 플레이어 제보 흐름

- 상단 정보 패널 또는 일시정지 메뉴에 `문제 신고` 버튼을 둔다.
- 문제 신고를 누르면 오프라인 AI 경기를 자동으로 일시정지한다.
- 게임 자체 렌더러가 현재 메인 화면, 미니맵과 주요 HUD 상태를 하나의 장면 이미지로 캡처한다.
- 다른 앱이나 휴대폰 화면 전체는 캡처하지 않는다.
- 전송 전에 플레이어가 캡처 이미지와 첨부 정보를 확인할 수 있다.
- 플레이어는 오류, 조작·UI, 밸런스, 성능과 개선 제안 중 유형을 선택한다.
- 진행 불가, 불편과 제안 중 영향 수준을 선택할 수 있다.
- 설명을 입력하고 필요한 경우 화면 위에 표시를 그려 문제 위치를 강조할 수 있다.
- 취소하면 캡처와 임시 데이터를 삭제하고 경기로 복귀한다.
- 전송 후에는 신고 번호를 표시하고 경기를 이어갈 수 있다.

### 30.2 자동 첨부 정보

- 현재 장면 이미지
- 게임 버전과 엔진 버전
- 지도, 종족, AI 난이도와 무작위 시드
- 현재 게임 틱과 경기 시간
- 유닛, 건물, 자원과 전장의 안개를 포함한 압축 상태 스냅샷
- 신고 직전 약 30초의 플레이어 명령과 주요 AI 결정 기록
- 선택 부대, 자동 기술 설정과 카메라 상태
- 기기 종류, 화면 크기, 브라우저 종류와 평균·최저 FPS
- 상태 검증값과 최근 오류 메시지

게임 밖의 개인정보와 다른 브라우저 탭 내용은 첨부하지 않는다.

### 30.3 네트워크와 저장

- 네트워크가 없으면 신고를 IndexedDB에 임시 저장하고 다음 연결 시 전송한다.
- 같은 신고를 중복 전송하지 않도록 고유한 신고 ID를 사용한다.
- 장면 이미지는 WebP로 압축하고 크기를 제한한다.
- 신고 메타데이터와 처리 상태는 D1에 저장한다.
- 장면 이미지, 상태 스냅샷과 진단 기록은 R2에 저장하는 구성을 우선한다.
- 제출 횟수를 제한하고 비정상적인 대량 전송을 차단한다.

### 30.4 개발자 관리 화면

- 개발자만 접근할 수 있는 Stark Rift 신고 관리 화면을 제공한다.
- 최신순, 유형, 영향 수준, 게임 버전, 종족, 지도와 처리 상태로 필터링할 수 있다.
- 목록에서 장면 미리보기, 신고 내용, 기기·성능 정보와 발생 시점을 확인한다.
- 상세 화면에서 장면 이미지, 최근 명령 기록과 게임 상태를 함께 확인한다.
- 상태 스냅샷과 명령 기록을 이용해 해당 시점부터 디버그 재현을 시작할 수 있다.
- 개발자는 담당자, 내부 메모, 관련 커밋과 수정 버전을 기록할 수 있다.

처리 상태는 다음과 같다.

1. 접수
2. 확인 중
3. 재현 완료
4. 수정 예정
5. 수정 완료
6. 보류
7. 중복
8. 재현 불가

### 30.5 신고 내역 확인

- 플레이어는 `내 신고` 목록에서 신고 번호, 작성 시각, 유형과 처리 상태를 확인할 수 있다.
- 처리 상태가 바뀌면 목록에 갱신된 시각과 개발자의 공개 답변을 표시한다.
- 로그인하지 않은 플레이어는 브라우저에 저장한 익명 신고 키로 자신의 신고만 조회한다.
- 브라우저 데이터를 삭제하면 익명 신고 목록을 복구할 수 없음을 안내한다.
