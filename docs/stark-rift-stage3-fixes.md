# 단계 3 검토 결함 보완

2026-11-03. 엔진 `0.6.1-stage3`; 저장/스키마 5, 통신 6 유지.

## 수정한 4건

1. **모서리 도착 위치 중복·진입 정체**
   - ID 순서의 목적지 예약기를 추가했다. 지형·건물·정지 유닛·다른 이동 목적지와 겹치지 않는 셀을 배정한다.
   - 벽이나 지도 경계로 제한되는 대열은 먼저 도착한 병력 사이로 후속 병력이 접근할 여유를 둔다.
   - A*가 도달 불가 위치를 대체할 때도 예약을 검사한다. 도착한 유닛과 위치 사수 유닛은 정적 경로 장애물로 반영하고 변경 시 캐시를 무효화한다.
   - 정지 유닛이 경로 장애물이 되므로 기존 지형 검사 테스트도 검사 대상 자신의 ID를 제외하도록 수정했다. 지형·다른 유닛 충돌 검사는 유지한다.
2. **A* 셀 사이의 건물 교차**
   - 이웃의 중심뿐 아니라 현재 셀부터 이웃까지 이동 구간을 검사한다.
   - 원형 장애물과 타일의 모서리를 얕게 스치는 경우도 누락하지 않도록 정수/BigInt 기반 구간 거리·교차 판정을 사용한다. 표시용 부동소수점 계산을 게임 규칙에 도입하지 않았다.
3. **적 재추적 누락**
   - 보이는 적이 접근 범위를 벗어나면 `arrived`를 해제하고 다시 접근한다.
   - 격자 중심의 반올림 때문에 접근 거리 바로 밖에서 멈춘 경우에는 안전한 마지막 접근 구간을 계산한다. 적이 여전히 범위 안에 있으면 불필요하게 이동하지 않는다.
4. **임시 부대의 대열 초기화**
   - 슬롯 미등록 유닛도 저장된 대열별로 묶어 이동 오프셋을 생성한다.
   - 다음 이동이나 정지·저장 복원이 전열로 덮어쓰지 않는다.

## 검증

- 전용 테스트 **180개**, 타입 검사, 전체 빌드, 기존 게임·한국어 조사 회귀 검사 통과.
- 내부 세션 별도 Vite 빌드에서 Worker 자산과 Pixi 동적 import 생성 확인.
- 지도 양쪽 모서리와 지도 밖 목적지에 10기를 보내 전원 도착·비중첩 확인.
- 크기가 다른 유닛의 모서리 도착, 정지한 유닛이 점유한 목적지, 벽 반대편 도달 불가 목적지의 대체 위치 검사.
- 적을 현재 추적자의 반대 방향으로 200단위 이동시켜 실제 접근 범위를 벗어나게 한 뒤 재추적 확인. 범위 안의 이동을 잘못된 테스트 실패로 취급하지 않는다.
- 선분 양 끝이 비어 있지만 중간에서 건물과 교차하는 경우와, 점 샘플링으로 놓칠 수 있는 얕은 교차를 검사.
- 임시 전열·종대·분산을 이동/정지/저장 복원 뒤에도 유지하는지 확인.
- 기존 50기 좁은 통로 이동, 탐색 예산, 저장·복원 결정성 검사를 유지했다.

실제 모바일 GPU·터치·메모리 성능 검증은 여전히 별도 과제다. 물리적으로 도착 공간이 전혀 없는 경우에는 임의로 중첩시키지 않고 `blocked`로 남긴다. 원작 전투·경제 콘텐츠와 공개 라우트는 추가하지 않았다.

## 2차 검토 결함 보완

2026-11-03. 엔진 `0.6.2-stage3`; 저장/스키마 5, 통신 6 유지. 상태 필드와 메시지 계약은 변경하지 않았다. 이동 결과가 바뀌므로 엔진 버전은 올렸으며 이전 엔진 저장본은 기존 버전 검사에 따라 호환 불가로 처리한다.

### 수정한 3건

1. **이동 중 유닛 사이의 얕은 구간 교차**: 이동자의 반경을 포함하는 선분 경계로 공간 해시 후보를 찾고 각 후보에 정확한 `segmentNearCircle` 판정을 적용한다. 검사 지점 사이를 빠져나가던 경우를 차단한다. ID 순서, 접선 허용, 지상/공중 층 분리와 죽은 개체 제외를 유지한다.
2. **태세 변경으로 A* 초기화**: `setStance`를 탐색 작업 취소보다 먼저 처리한다. 경로를 바꾸지 않는 태세 변경은 open/cost/parent/closed와 대기 순서를 그대로 유지한다. 이동·정지·대열 변경에 필요한 취소 동작은 유지한다.
3. **스와이프 후 이전 슬롯으로 선택 복귀**: 기존 선택 밖 유닛에서 시작하면 이전 슬롯 선택을 해제한다. 선택 안에서 시작하면 현재 슬롯과 연합 선택을 유지한다. 다음 스냅샷 동기화와 후속 지형 명령의 대상도 일치하도록 했다.

### 확인

- 전용 테스트 **188개**와 타입 검사 통과. 전체 Paperoid 빌드 및 기존 게임·한국어 조사 회귀 검사 통과.
- `SimulationSession` 별도 Vite 빌드에서 Pixi 동적 자산과 Worker 번들 생성 확인.
- 수평/대각선 이동 모두 **초기 비중첩**을 먼저 확인한 뒤 실제 이동 구간이 다른 이동 유닛과 교차하지 않는지 검사했다. 검토 초안의 첫 좌표는 초기 미세 중첩이 있었으므로 보완 검증에서는 두 번째 유닛을 `(1108,1167)`로 옮겨 초기 비중첩을 보장했다. 이 배치도 수정 전 코드에서 실패한다.
- 큰 반경의 객체가 여러 해시 셀에 걸치는 경우, 접선, 층 분리와 죽은 개체 제외를 검사했다.
- 96×96 지도에서 도달 불가 목표의 다중 틱 탐색에 매 틱 다른 태세를 적용했다. 태세 명령이 없는 기준 상태와 탐색 진행·이동 좌표가 같고, 중간 저장 복원 후 전체 체크섬도 같음을 확인했다.
- 실제 UI 콜백·스냅샷 효과를 모의 실행해 개별 전투 유닛, 일꾼, 기존 부대, 연합 부대의 선택과 후속 명령 대상을 검사했다. 세션 복원 후 선택과 승인 순번의 연속성도 검사했다. 브라우저 터치 E2E를 대신하는 검증은 아니다.
- 수정 전 소스에 새 회귀 검사를 적용하면 수평/대각선 충돌, 탐색 진행 보존, 전투 유닛/일꾼 선택 검사 총 5개가 실패한다. 수정 후 전체 188개가 통과한다.
- 기존 50기 좁은 통로 전원 통과·도착과 저장 결정성 검사도 통과했다.

### 현재 판정과 배포 제한

이번에 재현한 결함 3건은 수정·자동 검증을 마쳤다. 실제 모바일 GPU·터치·장시간 메모리와 프레임 성능은 여전히 미검증이므로 3단계 최종 완료로 올리지 않는다. 전투·경제 콘텐츠는 해당 후속 단계의 범위다.

기존 Sites 프로젝트와 공개 설정, 최신 배포 버전 227을 확인하고 새 소스 자격 증명을 발급받았으나, 선택된 환경에 Sites의 `site-workflow.mjs`/`build-site.mjs`가 없어 소스 동기화·패키징·배포는 수행하지 못했다. 최신 GitHub 소스를 배포 완료로 표시하지 않는다.
