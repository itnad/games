# 단계 6A — 버로우 연구·수동 상태 능력

2026-11-12. 엔진 `0.11.0-stage6a`, 저장·스키마 10, 통신 11. 단계 6 전체가 아닌 첫 상태 능력 구현이다.

## 플레이

`/stark-rift-dev` → 저그 → 기지 운영 → 새 테스트 시작. 드론으로 익스트랙터를 짓고 가스를 채취한다. 해처리 선택 후 **버로우 연구**(광물 100·가스 100)를 시작한다. 연구 완료 후 드론·저글링·히드라를 선택하여 **버로우 / 잠복 해제**를 누른다. 기존 전투·원거리·본부 공략 모드에서도 같은 연구를 진행할 수 있다.

## 연결 범위

- BWAPI v4.4.0 `TechType.cpp`의 Burrowing(ID 11): 100/100, 1,200프레임, 에너지 0. 프로젝트의 연구 시간 50% 규칙으로 500틱(25초). 출처와 SHA256은 `data/burrow-original.json`; 로컬 원본에서 `python tools/stark-rift-data/extract-burrow.py <TechType.cpp>`로 재생성한다.
- 해처리 연구 결제·진행률·완료·중복 방지·취소 전액 환불. 라바 생산·반복 생산과 연구는 동시에 진행된다. 다른 생산 건물의 연구/생산 상호 배제는 유지한다.
- 드론·저글링·히드라의 수동 토글. 잠복 상태에서는 이동·공격·순찰·채취·반납·건설 명령을 거절하며 자동 해제하지 않는다. 그룹·대열·태세, 체력과 운반 자원을 보존한다. 기존 추적·공격 이동 복귀 목표와 탐색 작업은 제거한다.
- 드론은 자원 점유를 해제하고 잠복한다. 해제 후에도 대기하며 자동 채취 버튼으로 작업을 다시 시작한다. 결제한 건설 예약이 남은 드론은 예약 취소 전 잠복을 거부해 건설 연결을 보존한다.
- 잠복 병력은 지상 이동·목적지 예약의 장애물이 아니다. 해제 위치에 다른 병력이 겹치면 잠복 상태를 유지하고 `blocked`를 반환한다. 겹친 잠복 병력의 동시 해제는 ID 순서로 공간을 확보한 유닛만 승인한다.
- 적 탐지기와 현재 시야가 모두 있어야 잠복 병력을 표시·선택·공격할 수 있다. 현재 병력 중 탐지기는 오버로드다. 아군과 탐지된 적에게만 납작한 땅더미 표시와 상태 플래그를 전달한다. 미탐지 적의 ID·좌표·상태는 렌더 패킷에 없다.
- 잠복 중 공격하지 않는다. 이미 발사된 적 투사체는 비행·명중 판정을 마치며 잠복으로 지워지지 않는다. 사망 시 잠복 상태·그룹·작업 참조를 정리한다.
- 상태, 연구, 미래 토글 명령, RNG와 체크섬을 저장한다. 6/7/8/9 형식의 원본 체크섬·엔진·원본 데이터 버전을 확인하고 새 형식으로 변환한다. 5C 정찰 기억과 비행 중 투사체의 `miss` 값을 보존한다. 처음 새 형식으로 덮어쓰기 전에 `.stage5c-backup`에 원문을 보관하며 백업 실패 시 원문을 덮어쓰지 않는다.

## 검증과 경계

자동 검증 결과와 사이트 버전·실제 배포 SHA는 별도 검증 영수증에 기록한다. Chromium 세로 화면 360×640·390×844에서 실제 터치·Worker·Pixi·저장 복구를 검사한다. 실제 Android/iOS 기기·물리 GPU 인수 검증과 구별한다.

잠복/해제는 승인된 시뮬레이션 틱에 적용한다. 원작 스프라이트 전환 애니메이션과 세부 프레임 재현, 추가 잠복 유닛·러커 공격, 영구 은폐 유닛·능동 클로킹, 수송선·탑승/하차·수송선 파괴 승객 처리, 적 전략 AI는 후속 작업이다. 세로 전용이며 가로 화면에서는 정지한다.
