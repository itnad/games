# 단계 3 — 선택·부대·이동

구현: 2026-11-02~03. 엔진 `0.6.0-stage3`, 스키마/저장 5, 통신 6.
후속 검토 수정: 엔진 `0.6.2-stage3`, `stark-rift-stage3-fixes.md` 참고. 최신 전용 테스트 221개 통과; 아래 166개는 최초 구현 시점의 기록이다.
최종 자동 검증 범위와 실제 기기 경계는 `docs/stark-rift-stage3-final-review.md`를 따른다. 계획은 `stark-rift-stage3-plan.md`를 따른다. 공개 라우트와 메인 게임 목록은 추가하지 않는다.

## 구현 결과

- 가시 스냅샷의 반경을 이용한 히트 검사, 개별 선택, 같은 종류·소유자·종류의 주변 최대 10기 선택을 구현했다. 기본 반경 4타일과 거리/ID 동률 규칙을 적용했다.
- 부대 슬롯 5개, 빈 슬롯 자동 등록, 슬롯 포화 시 선택, 기존 부대 이동·교체 확인, 보충·해제, 슬롯 가로 훑기 복수 선택, 두 번 터치 카메라 이동, 슬롯→전장 위쪽 스와이프 공격이동을 내부 UI에 연결했다. 일꾼 작업반은 슬롯에 등록하지 않는다.
- 이동·공격이동·집중공격 추적·정지·위치 사수·순찰 명령을 Worker 엔진에 등록했다. 보이는 적만 직접 지정할 수 있다. 사람의 명령은 수신 시 다음 실행 가능한 틱으로 보정하며 UI의 관측 틱과 순번은 유지한다.
- 전열·종대·분산 목적지 오프셋과 복수 부대의 별도 도착 영역을 생성한다. 통로에서는 경로를 따라 좁혀 이동하며 `transitFormation`을 종대로 기록하고 열린 공간에서 선택한 대열로 돌아간다. 각자의 속도로 이동하며 최종 도착 위치에서 대열을 완성한다.
- 128단위(반 타일) 격자와 정수 Manhattan A*, `(f,h,cell)` 동률 정렬, 직교 이웃을 사용한다. 통과 반경과 정적 지형·살아 있는 건물 장애물을 고려한다. 공중 이동은 지상 지형을 무시한다.
- 신규 탐색은 틱당 최대 4건, 노드 확장은 합계 8,000개다. 사용자/추적/AI 우선순위와 요청 틱/ID로 대기 순서를 정한다. 진행 중 open heap·cost·parent·closed 및 경로 캐시를 상태에 보존한다.
- 같은 목적지/크기/층/장애물 버전의 경로를 재사용한다. 가까운 별도 도착점도 끝부분이 직접 연결 가능하면 기존 통로 경로를 공유한다. 한 틱의 캐시 재사용 수를 별도로 기록한다.
- 도달 불가 목적지는 탐색 가능한 영역에서 Manhattan 거리가 가장 가까운 셀로 보정한다. 정적인 시작 셀 중심에 반경이 맞지 않으면 현재 위치에서 연결 가능한 근처 셀을 선택한다.
- 공간 해시는 2×2타일 셀에 원의 겹치는 모든 구간을 등록한다. ID 순서, 정수 후보 방향, 정수/BigInt 기반 이동 구간 충돌 검사로 유닛 중첩·빠른 이동 관통을 막는다. 경로 중간 지점은 직접 보이는 다음 지점까지 생략하며, 회피 뒤 직선 경로가 막히면 다시 요청한다.
- 건물 생성/삭제/위치/반경 변경은 장애물 버전과 캐시를 갱신한다. 살아 있는 건물의 일반적인 체력 변화는 지형 변경으로 취급하지 않는다.
- UI 상태 메시지에 승인 순번·부대 구성·태세를 전달한다. 변화는 즉시, 동일 값은 최대 5Hz로 전송한다. 선택·그룹 미리보기 표시, 목적지 터치와 카메라 드래그의 입력 중재를 연결했다.

## 검증

- 타입 검사와 테스트 **166개 통과**.
- 5개 부대 총 50기를 폭 1타일 통로로 이동시켜 전원 통과·도착을 확인했다. 이동 중 중첩 여부, 노드/시작 예산, 경로 재사용, 임시 종대 전환을 검사했다.
- 장애물 우회, 도달 불가 지점 보정, 공중 이동, 건물 이동 거부, 가시 적 추적, 사수와 순찰 왕복·정지 명령을 검사했다.
- 탐색이 진행 중인 틱에 저장·복원한 뒤 150틱의 전체 상태 체크섬을 비교했다. 기존 10,000틱 엔진 결정성과 Worker 별도 스레드 검증도 유지했다.
- 전체 Paperoid 빌드·한국어 조사/기존 게임 회귀 검사를 통과했다.
- `SimulationSession` 별도 Vite 빌드에서 내부 화면·Pixi 동적 import·Worker 자산 생성을 확인했다.

## 남은 범위

- 2차 최적화 이후 서버 시간 예산과 장시간 이동의 전원 도착은 통과했다. 초기 성능 초과 기록과 이후 해소 결과를 구분하며 `docs/stark-rift-stage3-performance-2.md`를 따른다.
- 브라우저 검증은 세로 전용이다. 가로 플레이를 지원하지 않으며 가로 전환/최초 접속의 차단과 세로 복귀 상태 보존을 검사한다. 실제 Android/iOS의 GPU·Worker 포함 메모리와 터치는 별도 실기기 인수 항목이다.
- 최신 장시간 브라우저 결과와 원격 반영은 최종 검토 기록을 따른다. 이전 단계의 미검증 설명을 현재 자동 검증 결과로 해석하지 않는다.
- 집중공격은 추적과 접촉 전 정지만 수행한다. 피해, 무기별 사거리, 자동 표적/자동 시전, 은폐 탐지와 전투 태세의 교전 판단은 단계 5~6에서 구현한다. 현재의 접근 정지 여유는 충돌을 막는 기술 값이며 원작 무기 사거리가 아니다.
- 내부 세션의 새 경기는 아직 빈 상태다. 본부·일꾼 생성, 생산·자원과 실제 원작 이동 수치는 단계 4~6 작업이다. 이동 테스트의 종류/속도/반경은 테스트 전용 값이다.
- 시야 공급자가 연결되기 전 기본 마스크는 미탐사다. 현재 내부 호스트를 완성된 플레이 화면이나 시야 시스템으로 해석하지 않는다.
- 건물 장애물은 반경으로 보수적으로 처리한다. 종족별 실제 건물 직사각형 footprint/애드온·크립·동력은 건설 단계에서 확장한다.
- 근거리 후보 회피는 결정적인 초기 구현이다. 교차 방향 대규모 부대, 다양한 반경, 건물 밀집 지형의 성능·교착 회귀는 콘텐츠가 연결될 때 계속 추가한다.
- 탐색 상태를 보존해 복원 결과를 맞췄으며, 전체 틱 복사/검증의 실제 모바일 비용은 별도로 측정해야 한다.

다음 단계는 경제·건설·생산이다. 실제 기기 검증 대기를 완료로 바꾸거나 미완성 게임을 공개하지 않는다.
